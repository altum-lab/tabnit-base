# link — 입력 수집, 매핑 실행, 판 비교 (주인 자리: C, H)

밖에서 들어오는 자료를 받아 개체와 관계로 옮기고, 새 판이 이전 판과 무엇이 다른지 찾아 변동으로 알린다.

읽을 문서: D6 (매핑 형식), D5. 관련 작업: C-01 ~ C-08.

## 맡는 것
- 파일 커넥터: 표 형식 파일을 행 단위로 읽는다.
- 매핑 실행: 행을 Pack의 매핑 정의에 따라 개체와 관계로 바꿔 적재한다. 유효기간과 출처를 붙인다.
- 원본 보관과 적재 이력.
- 판 비교: 새 판과 이전 판을 항목 단위로 비교해 추가, 변경, 삭제를 낸다.
- 변동 이벤트 발행: 바뀐 항목을 뒤 단계에 넘긴다.

## 지킬 것
- 파일 수준의 문제(인코딩, 필요한 열 없음)는 파일 전체를 거부한다. 행 수준의 문제는 그 행만 건너뛰고 **행 번호와 이유**를 남긴다.
- 다시 실행해도 중복되지 않는다. 같은 파일을 두 번 넣은 결과와 한 번 넣은 결과가 같아야 한다.
- 원본을 보관하지 못하면 적재도 하지 않는다. 모든 관계는 어느 파일의 어느 판에서 왔는지 따라갈 수 있어야 한다.
- 판 비교의 결과 순서를 고정한다. 이전 판이 없으면 전부 추가로 본다.
- 판이 바뀌어 끝난 관계는 지우지 않고 종료일을 넣는다(core의 API로).
- 저장은 core의 공개 API로만 한다. 뒤 단계가 실패하면 이벤트를 실패로 표시하고 다시 실행할 수 있게 둔다.
- 매핑은 Pack에 있다. 특정 파일의 열 이름을 코드에 넣지 않는다.

## 확인하는 방법
- 특정 파일의 모양을 전제로 코드를 쓰지 않는다. 열 구성과 유형은 Pack의 매핑 정의에서만 온다.
- 일반 시험을 먼저 둔다: 빈 파일, 이전 판이 없는 첫 판, 바뀐 것이 없는 판, 전부 바뀐 판, 행 순서만 바뀐 판, 잘못된 행이 섞인 파일, 같은 파일을 두 번 넣기.
- 그 위에 Pack마다 들어 있는 검증 질문을 돌린다.

## 하지 않는 것
- 영향 범위를 직접 계산하지 않는다(core). 규칙을 평가하지 않는다(rules).
- 데이터베이스 커넥터, 증분 수집은 1월 범위다. 외부 시스템에 접속하는 코드를 지금 만들지 않는다.
