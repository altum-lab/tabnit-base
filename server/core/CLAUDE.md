# core — 관계 저장, 시점 조회, 영향 범위 (주인 자리: A, F)

제품의 중심이다. 이 모듈의 결과가 틀리면 뒤의 모든 것이 틀린다. **이 모듈의 변경은 대표가 직접 검토한다.**

읽을 문서: D3 (정의의 기준), D5, D7. 관련 작업: SK-03, SK-05, A-01 ~ A-07.

## 맡는 것
- 개체, 속성 값, 관계를 유효기간, 출처, 기록한 때와 함께 저장. 식별자는 값에서 정해진다 (D5 1절).
- 시점 조회: 기준 날짜에 유효한 관계만 돌려준다.
- 영향 범위 계산: 변동 대상에서 관계를 따라가며 영향받는 대상을 찾고, 대상마다 근거 경로를 남긴다.
- 관계 지도용 조회(노드와 간선).

## 지킬 것
- 유효기간: **시작일 포함, 종료일 제외.** 종료일이 없으면 계속 유효. 경계 날짜의 시험을 반드시 둔다(시작일 당일, 종료일 전날, 종료일 당일).
- 모든 조회는 기준 날짜를 받는다. 기본값을 조용히 "오늘"로 두는 내부 함수를 만들지 않는다. 기본값은 API 층에서 한 번만 정한다.
- 결과 순서를 고정한다. 정렬 기준이 같으면 식별자 순. 재귀 질의의 결과를 정렬 없이 내보내지 않는다.
- 영향 범위: 관계가 돌아오는 구조에서도 끝나야 하고, 같은 대상은 한 번만 센다. 변동 대상 자신은 영향 대상에 넣지 않는다. 최대 깊이에서 멈췄을 때 그 너머에 아직 찾지 못한 대상이 있으면 그 사실을 결과에 담는다 (D3 7절).
- 근거 경로가 여럿이면 가장 짧은 것, 길이가 같으면 관계 식별자를 변동 대상 쪽부터 비교해 앞선 것을 남긴다.
- 관계를 지우지 않는다. 끝낼 때는 종료일을 넣는다. 같은 관계의 유효기간이 겹치는 저장은 거부한다.
- 성능은 측정해서 말한다. 목표와 측정값은 D5와 작업 카드(A-07)에 있다. 측정 없이 색인이나 캐시를 넣지 않는다.

## 확인하는 방법
- 이 모듈은 어떤 Pack이 들어와도 같은 방식으로 동작해야 한다. 특정 Pack의 유형 이름, 개체 수, 관계 모양을 전제로 코드를 쓰지 않는다.
- 일반 시험을 먼저 둔다: 빈 저장소, 관계가 하나도 없는 개체, 돌아오는 관계, 한 대상에 이르는 경로가 여럿인 경우, 깊이 한계, 유효기간 경계, 과거·현재·미래 시점.
- 그 위에 Pack마다 들어 있는 검증 질문을 돌린다. 예시 Pack이 통과해도 일반 시험이 없으면 끝난 것이 아니다.

## 하지 않는 것
- link, rules, pack에 의존하지 않는다. 변동, 규칙, 조치라는 개념을 이 모듈에 넣지 않는다.
- 표준 형식(RDF) 내보내기(A-11), 조회 범위 제한(A-12)은 당김 범위다. 작업 카드가 있고 필수 범위가 밀리지 않을 때만 만든다 (D1 4절).
- Pack 의 정의를 저장하지 않는다. 관계 유형마다의 영향 방향과 최대 깊이는 부르는 쪽이 인자로 넘긴다 (D2 AD-35, AD-66).
