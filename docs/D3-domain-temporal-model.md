# D3 도메인·시점 모델

상태: 초안 (대표 확정 전) · 담당: 대표

> 이 문서가 기준입니다. 코드와 다르면 문서를 먼저 봅니다.

> **이 초안을 읽는 법.** 저장소에 이미 적혀 있던 정의와 규칙만 옮겼다. 대괄호가 출처다. 새로 정한 것은 없다. 저장소에 근거가 없는 곳은 채우지 않고 마지막 절 "결정 필요"에 질문으로 남겼다. 본문에서 그런 곳은 **(결정 필요 n)** 으로 표시했다. 대표가 확정하면 상태 줄을 고치고 출처 표시와 이 안내를 지운다.
>
> 출처 표기: [C n절] 맨 위 `CLAUDE.md`, [모듈 이름] 그 모듈의 `CLAUDE.md`, [규칙 engine] `.claude/rules/engine.md`, [보드 기능 번호] 개발 보드의 기능, [코드] `server/core` 의 `ValidityPeriod`.
>
> 이 문서의 예시는 지어낸 것이다. 개체 이름은 가, 나, 다 로 쓴다. 특정 Pack 의 유형 이름을 쓰지 않는다.

## 1. 한눈에

```
Pack ──(온톨로지: 유형)──▶ 개체, 관계
입력 자료의 새 판 ──(매핑)──▶ 개체, 관계 (유효기간, 출처)
새 판 vs 이전 판 ──(판 비교)──▶ 변동
변동 대상 + 기준 날짜 ──(관계를 따라감)──▶ 영향 범위 (영향 대상, 근거 경로)
영향 범위 + 규칙 ──(규칙 실행)──▶ 조치 (근거 조항, 기한, 우선순위)
조치 ──(담당자)──▶ 확정 또는 보류
```

[C 1절]

core 가 아는 것은 개체, 관계, 유효기간, 영향 범위까지다. 변동, 규칙, 조치는 core 의 개념이 아니다. [core]

## 2. 개체

- 개체는 관계로 이어지는 대상이다. 개체의 유형은 Pack 의 온톨로지가 정한다. 엔진 코드는 유형 이름을 모른다. [보드 PACK-01.1] [C 8절]
- 개체에는 식별자가 있다. 결과의 순서를 정할 때 마지막 기준이 된다. [C 8절]
- 온톨로지는 유형과 함께 속성을 정의한다. [pack] 개체가 속성 값을 어떻게 갖는지는 정해지지 않았다 **(결정 필요 1)**.
- 없는 개체를 조회하면 빈 목록이 아니라 오류로 알린다. [보드 CORE-02]

## 3. 관계

- 관계는 개체와 개체를 잇는다. 관계의 유형은 Pack 의 온톨로지가 정한다. [보드 PACK-01.1]
- 모든 관계에는 유효기간과 출처가 있다. [C 8절] [core]
- 출처는 그 관계가 어느 파일의 어느 판에서 왔는지다. 모든 관계는 출처를 따라갈 수 있어야 한다. [link]
- 없는 개체를 가리키는 관계는 저장을 거부한다. [보드 CORE-01]
- 같은 관계의 유효기간이 겹치는 저장은 거부한다. [core] 무엇이 "같은 관계"인지는 정해지지 않았다 **(결정 필요 2)**.
- 관계를 지우지 않는다. 끝난 관계는 종료일을 넣는다. [C 8절]
- 관계에 방향이 있는지, 있다면 어떻게 읽는지는 정해지지 않았다 **(결정 필요 3)**.

## 4. 유효기간

- 유효기간은 시작일과 종료일이다. **시작일은 포함하고 종료일은 제외한다.** [C 8절]
- 종료일이 없으면 계속 유효하다. [C 8절]
- 시작일은 반드시 있다. 종료일이 있으면 시작일보다 뒤여야 한다. 시작일과 종료일이 같은 유효기간은 만들 수 없다. [코드]
- 단위는 날짜다. 시각은 없다. [코드]

기준 날짜 d 에 관계가 유효하다는 것은 다음과 같다. [코드]

```
시작일 <= d  그리고  (종료일이 없다  또는  d < 종료일)
```

## 5. 시점 조회

- 관계를 읽는 모든 조회는 기준 날짜를 받는다. 기준 날짜 없이 "지금 유효한 것"을 암묵적으로 읽는 조회를 만들지 않는다. [C 8절]
- 엔진 안에는 기준 날짜의 기본값이 없다. 기준 날짜가 빠진 요청은 API 층에서 한 번만 오늘로 정해 넘기고, 응답에 어느 시점으로 답했는지 담는다. [core] [api] [보드 CORE-03]
- 시점 조회는 개체 식별자와 기준 날짜를 받아, 그 날짜에 유효한 관계만 돌려준다. [보드 CORE-03]
- 날짜 형식이 틀리면 거부한다. [보드 CORE-03]
- 결과의 순서는 고정한다. 정렬 기준이 같은 항목은 식별자 순이다. [C 8절] [보드 CORE-03.2] 첫째 정렬 기준은 정해지지 않았다 **(결정 필요 4)**.
- 과거, 현재, 미래의 어느 날짜든 기준 날짜가 될 수 있다. [core]

### 예시

개체 가 에 관계가 셋 있다.

| 관계 | 잇는 개체 | 시작일 | 종료일 |
|---|---|---|---|
| R1 | 가 — 나 | 2026-03-01 | 2026-06-01 |
| R2 | 가 — 다 | 2026-06-01 | 없음 |
| R3 | 가 — 라 | 2026-01-01 | 2026-03-01 |

기준 날짜별로 개체 가 의 시점 조회가 돌려주는 관계는 다음과 같다.

| 기준 날짜 | 돌려주는 관계 | 까닭 |
|---|---|---|
| 2025-12-31 | 없음 (빈 목록) | 어느 관계도 아직 시작하지 않았다 |
| 2026-01-01 | R3 | R3 의 시작일 당일. 시작일은 포함한다 |
| 2026-02-28 | R3 | R3 의 종료일 전날 |
| 2026-03-01 | R1 | R3 는 종료일 당일이라 빠진다. R1 은 시작일 당일이라 들어온다 |
| 2026-05-31 | R1 | R1 의 종료일 전날 |
| 2026-06-01 | R2 | R1 은 종료일 당일이라 빠진다. R2 가 시작한다 |
| 2030-01-01 | R2 | 종료일이 없으면 계속 유효하다 |

경계 날짜(시작일 당일, 종료일 전날, 종료일 당일)의 시험은 반드시 둔다. [core]

## 6. 판과 변동

- 입력 자료는 판으로 들어온다. 새 판의 행은 Pack 의 매핑 정의에 따라 개체와 관계로 바뀌고, 유효기간과 출처가 붙는다. [link] 유효기간의 시작일이 어디서 오는지는 정해지지 않았다 **(결정 필요 5)**.
- 판 비교는 새 판과 이전 판을 항목 단위로 비교해 추가, 변경, 삭제를 낸다. 이전 판이 없으면 전부 추가로 본다. [link] [보드 LINK-04]
- 판 비교의 결과 순서는 고정한다. [link]
- 판이 바뀌어 끝난 관계는 지우지 않고 종료일을 넣는다. [link] 이때 넣는 종료일이 어느 날짜인지는 정해지지 않았다 **(결정 필요 5)**.
- 같은 파일을 두 번 넣은 결과와 한 번 넣은 결과는 같다. [link]
- 변동은 판 비교에서 나온 바뀐 항목이다. 바뀐 항목은 변동 이벤트로 뒤 단계에 넘어간다. [보드 LINK-05]
- 바뀐 항목에서 "변동 대상" 개체를 정하는 방법은 정해지지 않았다 **(결정 필요 6)**.

## 7. 영향

- 영향 범위 계산은 변동 대상, 기준 날짜, 최대 깊이를 받는다. 변동 대상에서 기준 날짜에 유효한 관계를 따라가며 영향받는 대상을 찾는다. [보드 CORE-04] [core]
- 돌려주는 것은 영향 대상 목록과 유형별 수다. [보드 CORE-04]
- 영향 대상마다 근거 경로가 붙는다. 어떤 관계를 따라 도달했는지다. 근거 없는 결과를 만들지 않는다. [C 8절] [보드 CORE-04.1]
- 근거 경로가 여럿이면 가장 짧은 것을, 길이가 같으면 식별자 순으로 앞선 것을 남긴다. [core] 경로끼리 식별자 순을 비교하는 방법은 정해지지 않았다 **(결정 필요 7)**.
- 관계가 돌아오는 구조에서도 계산은 끝나야 한다. 같은 대상은 한 번만 센다. [core]
- 최대 깊이를 넘으면 멈추고 그 사실을 결과에 담는다. [core] 최대 깊이의 기본값과 깊이를 세는 법은 정해지지 않았다 **(결정 필요 8)**.
- 결과의 순서는 고정한다. 재귀 질의의 결과를 정렬 없이 내보내지 않는다. [core] [규칙 engine]
- 어느 방향의 어느 유형 관계를 따라가는지, 변동 대상 자신이 영향 범위에 드는지는 정해지지 않았다 **(결정 필요 3, 9)**. 그래서 이 절에는 예시를 두지 않았다.

## 8. 조치

- 규칙 실행은 영향 범위와 Pack 의 규칙 목록을 받아 해당하는 규칙을 고른다. 규칙의 내용은 Pack 에 있다. [rules] [보드 RULE-01]
- 조치는 해당 규칙과 영향 대상에서 만든다. 조치에는 근거 규칙, 근거 조항과 그 판, 대상, 기한, 우선순위가 붙는다. [rules] [보드 RULE-02]
- 근거 조항이 없는 조치는 만들지 않는다. [C 8절] [rules]
- 기한은 기준 날짜를 받아 계산한다. 현재 시각을 읽지 않는다. [rules]
- 같은 입력에는 같은 조치가 같은 순서로 나온다. 평가 순서는 D8 이 정한다. 우선순위가 같으면 규칙 번호 순이다. [rules]
- 규칙 하나가 평가에 실패해도 나머지는 계속 평가하고, 실패한 규칙과 이유를 결과에 담는다. [rules]
- 담당자는 조치를 확정하거나 보류한다. 누가 언제 했는지 남긴다. 이미 확정된 조치는 다시 확정할 수 없다. [rules] [보드 RULE-03]
- 조치의 상태가 무엇무엇이고 어떻게 옮겨 가는지는 정해지지 않았다 **(결정 필요 10)**.

## 9. 결정 필요

1. **개체의 속성.** 개체는 속성 값을 갖는가? 갖는다면 속성 값이 판마다 바뀔 때 어떻게 남기는가? 유효기간은 관계에만 있는가, 개체나 속성 값에도 있는가?
2. **"같은 관계"의 기준.** 유효기간이 겹치면 거부하는 "같은 관계"는 무엇이 같은 것인가? (예: 잇는 두 개체와 관계 유형이 같으면 같은 관계) 유효기간이 맞닿는 것(앞의 종료일과 뒤의 시작일이 같은 날)은 겹침이 아닌 것으로 보는가? 4절의 정의대로라면 겹치지 않는다.
3. **관계의 방향.** 관계에 방향(어디서 어디로)이 있는가? 시점 조회는 개체가 어느 쪽 끝에 있든 돌려주는가? 영향 범위는 어느 방향으로 따라가는가? 방향을 Pack 의 온톨로지가 관계 유형마다 정하는가?
4. **시점 조회의 정렬 기준.** 식별자는 마지막 기준이다. 첫째 기준은 무엇인가? (관계 유형, 시작일, 상대 개체 등) 식별자만으로 정렬하는가?
5. **유효기간의 날짜가 오는 곳.** 매핑이 붙이는 시작일은 입력 행의 열에서 오는가, 판의 날짜에서 오는가? 판이 바뀌어 관계가 끝날 때 넣는 종료일은 새 판의 어느 날짜인가? 판에는 날짜가 하나인가 (적용일, 투입일)?
6. **변동 대상.** 바뀐 항목(행)에서 영향 범위 계산의 출발점인 변동 대상 개체를 어떻게 정하는가? 항목 하나가 개체 여럿에 걸리면? 삭제된 항목의 변동 대상은?
7. **경로의 식별자 순.** 길이가 같은 근거 경로 둘을 비교할 때 무엇의 식별자를 어떤 순서로 비교하는가? (경로 위 관계의 식별자를 앞에서부터, 경로 위 개체의 식별자를 앞에서부터 등)
8. **최대 깊이.** 기본값은 얼마인가? 변동 대상에서 관계 하나를 건넌 대상이 깊이 1 인가? 한계를 넘어 멈췄을 때 그때까지 찾은 대상은 돌려주는가?
9. **영향 범위에 드는 것.** 변동 대상 자신은 영향 대상에 드는가? 모든 관계 유형을 따라가는가, Pack 이 따라갈 유형을 정하는가? "유형별 수"의 유형은 개체 유형인가?
10. **조치의 상태.** 조치의 상태는 무엇무엇인가? 보류한 조치를 나중에 확정할 수 있는가? 확정한 조치를 되돌릴 수 있는가? 같은 변동으로 규칙을 다시 실행하면 이미 있는 조치는 어떻게 되는가?
11. **과거 시점의 답이 바뀌는가.** 나중에 들어온 판이 과거의 유효기간을 고치면, 같은 과거 기준 날짜의 조회 결과가 달라진다. 이것을 허용하는가? "그때 알고 있던 대로" 답해야 하는 경우가 있는가? 있다면 유효기간과 별개로 기록한 때를 남겨야 한다.
12. **관계 기본 조회와 기준 날짜.** 보드의 CORE-02 관계 기본 조회는 입력이 개체 식별자뿐이다. "관계를 읽는 모든 조회는 기준 날짜를 받는다"와 어긋난다. CORE-02 도 기준 날짜를 받는가, 유효기간과 무관하게 전부 돌려주는 조회로 따로 두는가?
13. **"오늘"의 기준.** API 층이 기준 날짜의 기본값으로 쓰는 오늘은 어느 시간대의 날짜인가?
