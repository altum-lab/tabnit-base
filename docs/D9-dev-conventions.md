#### B-03 제조 안전 Pack 완성

- 모듈: pack (자료는 `packs/manufacturing-safety`)
- 수용 기준: 시연 앱의 가상 데이터 전체가 Pack과 입력 파일로 표현된다. 코드에 이 Pack의 용어가 없다
- 선행 작업: B-01
- 진행 (2026-11-22): 시연 자료의 설계도(클래스 11개, 관계 유형 11개, 규칙 팩, 검증 질문)를 본떠 Pack 을 만들었다 (D2 AD-284 ~ AD-288). 유형 11개와 상위 유형 하나, 관계 유형 11개, 속성 26개, 입력 자료 20개와 그 매핑, 규칙 6개(물질안전자료의 변경, 인원의 배치 변경), 예시 입력 파일 26개(개체 157개, 관계 215개), 시나리오 하나(26단계)와 검증 질문 22개. 이름은 모두 지어냈다. 엔진 코드를 고치지 않았고, 이 Pack 의 용어를 일반성 검사의 목록에 더했다 (엔진 코드에 없다). 검증 질문 22개가 모두 통과하고 두 번 돌린 결과가 같다. 정답은 예시 입력 파일에서 엔진과 따로 계산했다 (`tools/packs/manufacturing-safety-build.py`). **카드는 닫히지 않는다**: 시연의 시나리오 13개 가운데 둘의 규칙만 옮겼고, 형식이 모자라 규칙이 뜻보다 넓게 걸리며 (D6 "결정 필요" 15번), 정답은 초안이고, 질문은 길이가 같은 근거 경로가 둘인 경우를 묻지 않는다. 시연 자료 가운데 실제 문서(공개된 물질안전자료 원본과 그것을 읽어 낸 파일)는 읽지 않았다.
- 진행 (2026-11-22, 규칙의 형식 넓히기): 이 카드의 이어지는 일로 규칙의 형식 셋을 넓혔다 (D2 AD-289 ~ AD-293, D8 2절·3절·7절, D5 4절·5절). 규칙이 변동이 나온 입력 자료(`tabnit:whenInputSource`)와 그 행에서 바뀐 속성·관계 유형(`tabnit:whenChanged`)을 가리고, 조건이 속성 값을 판의 적용일이나 다른 대상의 속성과 견준다. pack(읽기·검증·저장), link(변동 이벤트에 바뀐 것을 남긴다), rules(평가), api(넘겨주기)와 스키마 변경 파일 V14 가 함께 바뀌었다. 제조 안전 Pack 의 규칙 여섯을 새 항목으로 좁혔고, 시나리오에 물질의 이름만 고친 판과 교육 이수일만 바뀐 인원을 더해 시나리오가 27단계, 예시 입력 파일이 27개, 검증 질문이 26개가 되었다 (전체 40개 통과, 두 번 돌린 결과가 같다). 카드는 여전히 닫히지 않는다: 시연의 나머지 시나리오의 규칙이 남아 있다.

- 수용 기준: 변경마다 일반 시험과 모든 Pack의 검증 질문이 돌고, 같은 데이터로 두 번 돌린 결과가 같다
- 선행 작업: SK-06, E-01
- 진행 (2026-11-21): 실행기가 시나리오마다 빈 저장소에서 두 번 돌려 결과가 같은지 본다 (다르면 어느 질문인지 알리고 실패로 끝난다). 변경마다 도는 구성(`ci.yml`)에 넣었고, 밤 구성은 이미 이 명령을 부르고 있었다. 두 구성 모두 보고를 실행의 요약에 붙인다. 하지 않은 것: 직전 main 의 통과 수와 견주기, 예시 Pack 둘 (내용이 없다).
- 할 일 (2026-11-22, D2 AD-336): 실행기가 Pack 마다 같은 입력 자료에 판이 둘 이상 들어오는 단계가 있는지, 시점 조회 질문의 조회 시점이 셋 이상인지도 확인한다 (AD-332).

#### E-06 역할 2종

- 모듈: common, api
- 수용 기준: 담당자는 확정만, 관리자는 Pack 적재까지 할 수 있다
- 선행 작업: E-02
- 진행 (2026-11-21): 역할마다 할 수 있는 일을 나눴다 (D2 AD-270 ~ AD-272, D7 2절과 10절, 규격의 `loadPack`). 관리자는 담당자의 일을 모두 한다. 어느 API 를 어느 역할이 부르는지는 api 의 보안 설정 한 곳에 적는다. 관리자만 부르는 Pack 적재 API 를 만들었다: 서버의 Pack 폴더(설치 설정 `tabnit.packs-dir`)에 있는 Pack 을 이름으로 골라 적재한다. 수용 기준은 자동 시험으로 확인된다 (`RolesApiTests`): 담당자는 보기, 판 올리기, 확정을 부를 수 있고 Pack 적재는 403 이며, 관리자는 Pack 을 적재하고 담당자의 일도 한다. 하지 않은 것: 권한이 없어 거부한 요청을 감사 기록에 남기는 것 (E-03. 지금은 서버의 로그에만 적는다), Pack 적재의 화면과 Pack 폴더의 목록, 역할을 바꾸는 기능 (D-12), 판을 처리하는 중의 Pack 적재를 막는 것. 화면은 바꾸지 않았다 (숨길 버튼이 없다).

#### E-08 전체 흐름 자동 시험 (화면)

- 모듈: verify (시험은 web, 밤 구성은 `.github/workflows`)
- 수용 기준: 새 판 투입부터 확정까지 화면 시험이 매일 밤 돈다
- 선행 작업: D-07, E-04
- 진행 (2026-11-21): 담당자 한 사람이 화면만으로 하는 한 줄기 시험을 더했다 (`web/tests/flow.spec.ts`): 로그인하고, 판을 올리고, 그 변동의 조치로 가서 확정하고, 이력에 자기 아이디가 남은 것을 본다. 서버를 직접 부르지 않는다. 밤마다 도는 구성(`nightly.yml`)에 화면 흐름 시험을 넣었고, 실패하면 그 화면과 기록을 올린다. 화면 시험은 변경마다 도는 구성(`ci.yml`)에는 SK-07 부터 들어 있었다. 선행 작업 E-04 (검증 질문 자동 실행)는 아직 하지 않았다: 실행기(`verify/run.sh`, SK-06)가 없어 밤 구성의 그 단계는 건너뛴다. 하지 않은 것: Pack 적재부터 시작하는 줄기 (Pack 은 시험용 서버가 미리 적재한다), 관리자의 줄기, 크롬 계열 말고 다른 브라우저.

#### E-18 계정 관리 명령과 감사 기록 보강

- 선행 작업: E-02, E-05
