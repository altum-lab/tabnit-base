# verify-core — 검증 질문을 읽고 정답과 견준다 (주인 자리: J)

검증 질문 파일(`questions/*.yaml`)을 읽고, 제품이 준 답을 정답과 견줘 질문마다 통과와 실패를 낸다. 명령줄 실행기(`verify`)와 api (화면에서 검증 질문 돌리기, 카드 E-23)가 함께 쓴다. 견주는 코드가 하나라 두 결과가 갈리지 않는다 (D2 AD-422).

읽을 문서: D4. 관련 작업: SK-06, E-04, T-08, E-23.

## 맡는 것
- 질문 파일을 읽고 틀린 파일은 어느 파일, 어느 질문, 어느 항목인지 알리며 거부한다.
- 질문의 종류마다 제품에 묻고 (묻는 길은 부르는 쪽이 `Product` 로 준다) 정답과 견준다. 목록은 순서까지, 근거(경로와 출처)까지 견준다.
- 보고의 글(질문마다의 줄, 요약)을 만든다.

## 지킬 것
- **제품의 어느 모듈에도 기대지 않는다** (common, core, pack, link, rules, api 를 들여오지 않는다). 기대면 api 가 이 모듈을 쓸 때 의존이 돈다. 제품에 묻는 길이 더 필요하면 `Product` 에 메서드를 더하고, 부르는 쪽(verify 의 HTTP, api 의 서버 안 호출)이 채운다.
- **정답을 고쳐 통과시키지 않는다.** 정답은 Pack 의 질문 파일에 있고 대표가 정한다. 이 모듈의 코드에 정답, Pack 의 유형 이름, 개체 수를 넣지 않는다.
- 질문을 건너뛰지 않는다. 질문 하나가 오류를 내도 나머지는 계속 묻는다. 아직 만들지 않은 종류의 질문은 실패로 보고한다 (D4 4절, 5절).
- 같은 입력에는 같은 결과. 질문은 id 의 글자 코드 순으로 묻고 보고한다. 현재 시각과 난수를 쓰지 않는다.
- 묶음째로 견준다. 글자로 적은 것은 보고에만 쓴다: 값 안의 쉼표나 괄호 때문에 다른 묶음이 같은 글자가 될 수 있다.
- 오류의 문구에 서버의 폴더 경로를 담지 않는다. 이 모듈의 문구는 화면의 답에 그대로 나갈 수 있다 (D2 AD-423).
- 질문의 종류, 항목, 골든셋의 번호의 꼴을 바꾸려면 D4 를 같은 변경에서 고친다 (D2 AD-421, AD-426).
- 일반성 검사(`tools/check-generality.sh`)가 이 모듈을 본다.

## 하지 않는 것
- 판을 올리거나 저장소를 고치지 않는다. 묻고 견줄 뿐이다. 시나리오의 단계를 올리는 일은 부르는 쪽이 한다.
- HTTP 를 부르지 않는다. 외부 네트워크와 AI 모델을 부르지 않는다.
- 전수 대조(엔진과 따로 계산한 값과 견주는 것)를 화면의 길에서 돌리지 않는다. 대조의 파일을 읽고 견주고 보고하는 코드는 이 모듈에 있지만, 밖에 연 길(`VerificationQuestions`)은 질문 파일만 읽는다: 전수 대조는 명령줄 실행기(`verify`)만 돌린다 (D2 AD-422).
