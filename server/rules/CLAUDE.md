# rules — 규칙 실행, 조치 생성, 확정 (주인 자리: G)

영향 범위에 Pack의 규칙을 적용해 해야 할 일(조치)을 만들고, 담당자의 확정과 보류를 기록한다. **규칙 실행의 변경은 대표가 직접 검토한다.**

읽을 문서: D8 (실행 방식의 기준), D6. 관련 작업: B-04 ~ B-08.

## 맡는 것
- 규칙 실행: 영향 범위와 규칙 목록을 받아 해당하는 규칙을 고른다.
- 조치 생성: 근거 조항, 기한, 우선순위를 붙인다.
- 확정, 보류, 그 이력.

## 지킬 것
- 규칙 실행기는 직접 만든 것을 쓴다. 외부 규칙 엔진을 들이지 않는다.
- 평가 순서는 D8을 따른다. 우선순위는 수가 작을수록 먼저고, 같으면 규칙 번호 순(글자 코드 순). 같은 입력에 같은 조치가 같은 순서로 나와야 한다.
- 규칙 하나가 평가에 실패해도 나머지는 계속 평가하고, 실패한 규칙과 이유를 결과에 담는다. 조용히 건너뛰지 않는다.
- **근거 조항이 없는 조치는 만들지 않는다.** 조치에는 근거 규칙, 근거 조항과 그 판, 대상이 붙는다. 근거 조항은 변동이 생긴 행의 주 개체다. 영향 범위와 조치는 판을 투입한 직후에 한 번 계산해 저장한다.
- 변동 이벤트, 규칙, 대상이 같으면 같은 조치다. 다시 실행해도 새로 만들지 않는다.
- 기한 계산에 현재 시각을 직접 읽지 않는다. 기한은 변동이 나온 판의 적용일에 규칙이 적은 일수를 더한 날짜다.
- 이미 확정된 조치는 다시 확정할 수 없다. 확정과 보류에는 누가 언제 했는지 남긴다.
- 규칙의 내용은 Pack에 있다. 특정 규칙의 조건을 코드에 넣지 않는다.
- AI 모델을 부르지 않는다.

## 확인하는 방법
- 특정 규칙이나 특정 조치 수를 전제로 코드를 쓰지 않는다.
- 일반 시험을 먼저 둔다: 규칙이 없는 Pack, 해당하는 규칙이 없는 영향 범위, 한 대상에 규칙 여럿이 걸리는 경우, 우선순위가 같은 규칙, 평가에 실패하는 규칙, 근거 조항이 빠진 규칙.
- 그 위에 Pack마다 들어 있는 검증 질문을 돌린다.

## 하지 않는 것
- 규칙 적용 전 미리보기(B-11), 담당자 배정과 알림(B-12)은 당김 범위다. 작업 카드가 있고 필수 범위가 밀리지 않을 때만 만든다 (D1 4절).
