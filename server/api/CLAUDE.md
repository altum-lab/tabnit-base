# api — 화면과 외부가 부르는 API (주인 자리: I)

D7의 API 계약을 구현한다. 업무 처리는 각 모듈이 하고, 이 모듈은 받고, 확인하고, 넘기고, 돌려준다.

읽을 문서: D7 (계약의 기준). 관련 작업: D-02, SK-07.

## 지킬 것
- **계약이 먼저다.** OpenAPI 규격 파일(`docs/api/openapi.yaml`)을 먼저 고치고 그에 맞춰 구현한다. 구현을 먼저 하고 규격을 맞추지 않는다.
- 규격을 바꾸는 일은 설계 변경 절차를 따른다. 화면의 호출 코드는 규격에서 만든다.
- 관계를 읽는 모든 API는 **조회 시점**(`asOf`)을 받는다. 빠지면 여기서 한 번만 오늘로 정해 넘기고, 응답에 어느 시점으로 답했는지 담는다. 오늘은 설치 설정의 시간대(`tabnit.time-zone`, 기본 Asia/Seoul)에서의 날짜다.
- 결과에는 근거로 가는 연결을 담는다(영향 대상의 경로, 조치의 근거 조항).
- 업무 로직을 여기에 쓰지 않는다. 계산과 판단이 필요하면 해당 모듈의 공개 API를 부른다.
- 순서를 잡는 일은 여기서 한다. 변동 이벤트를 읽어 core 의 영향 범위 계산과 rules 의 규칙 실행을 차례로 부르고, 성공과 실패를 이벤트에 표시한다. 영향 방향과 최대 깊이의 기본값은 pack 에서 읽어 core 에 인자로 넘긴다 (D2 AD-44, AD-66).
- 모든 요청은 로그인과 역할을 확인하고 감사 기록에 남긴다(common). 뼈대 단계에는 이것 없이 연다 (D2 AD-80). 로그인(E-02)과 감사 기록(E-05)이 끝나는 변경에서 닫는다.
- 오류는 공통 오류 형식(RFC 9457 에 `code`, `field`)으로 낸다. 내부 예외 문구나 스택을 그대로 내보내지 않는다.
- 목록 응답의 순서는 모듈이 준 순서를 바꾸지 않는다.
