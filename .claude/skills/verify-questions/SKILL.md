# 검증 질문 실행

1. `bash verify/run.sh` 를 돌린다. 실행기가 아직 없으면 (SK-06 전) 그렇게 알리고 모듈 시험만 돌린다.
2. 같은 명령을 한 번 더 돌려 결과가 같은지 본다. 다르면 어느 질문이 달랐는지 적는다. 이것은 결함이다.
3. 보고 형식:
   - Pack 별 통과 수 / 전체 수, 직전 main 의 통과 수와의 차이
   - 실패한 질문의 번호, 기대한 값, 실제 값, 기준 날짜
4. 통과 수가 줄었으면 끝난 것이 아니다. 원인을 찾을 때는 `superpowers:systematic-debugging` 의 순서(다시 만들기, 범위 좁히기, 원인 확인, 고치기)를 따른다.
5. **정답 파일을 고쳐 통과시키지 않는다.** 정답이 틀렸다고 판단되면 근거(조문, 경로, 날짜)를 적어 사람에게 묻는다.
