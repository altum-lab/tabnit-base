## 1. 한눈에

```
Pack ──(온톨로지: 유형, 속성, 영향 방향)──▶ 정의
입력 자료의 새 판 ──(매핑)──▶ 개체, 속성 값, 관계 (유효기간, 출처)
새 판 vs 앞 판 ──(판 비교)──▶ 변동
변동 대상 + 기준 날짜 ──(관계를 따라감)──▶ 영향 범위 (영향 대상, 근거 경로)
영향 범위 + 규칙 ──(규칙 실행)──▶ 조치 (근거 조항, 기한, 우선순위)
조치 ──(담당자)──▶ 확정 또는 보류
```

[C 1절]

- core 가 아는 것은 개체, 속성 값, 관계, 유효기간, 영향 범위까지다. 변동, 규칙, 조치는 core 의 개념이 아니다. [core]
- Pack 적재는 정의만 저장한다. 개체와 관계는 항상 입력 자료가 link 의 매핑을 거쳐 들어온다. [AD-45]
- 변동에서 영향 범위 계산, 규칙 실행으로 이어지는 순서는 api 가 잡는다. link 는 변동 이벤트를 저장하고, api 가 core 와 rules 를 차례로 부른다. [AD-44]

## 2. 개체

- 개체는 관계로 이어지는 대상이다. 개체의 유형은 Pack 의 온톨로지가 정한다. 엔진 코드는 유형 이름을 모른다. [보드 PACK-01.1] [C 8절]
- 유형은 상위 유형을 가질 수 있다. 개체는 가장 구체적인 유형 하나로 저장하고, 상위 유형에 걸린 관계 유형, 속성, 규칙은 하위 유형에도 적용된다. [AD-88] (D6 5절)
- 개체의 식별자는 입력의 키에서 정해진다: (Pack, 개체 유형, 입력의 키). 빈 데이터베이스에 어떤 순서로 다시 적재해도 같은 개체는 같은 식별자를 갖는다. [AD-37]
- 없는 개체의 관계나 속성 값을 조회하면 빈 목록이 아니라 오류로 알린다. [보드 CORE-02] 개체가 있는지를 묻는 조회(식별자로 개체를 읽는다)는 오류가 아니라 없다고 답한다. [AD-218]

### 속성 값

- 온톨로지는 개체 유형마다 속성을 정의한다. [pack]
- 속성 값에도 유효기간이 있다. 규칙은 4절과 같다. 기준 날짜에 유효한 값을 돌려준다. [AD-39]
- 같은 개체의 같은 속성에는 기준 날짜에 유효한 값이 많아야 하나다. 유효기간이 겹치는 값은 출처와 무관하게 저장을 거부하고 이유를 남긴다. 이 점이 관계와 다르다(3절). [AD-53]
- 속성 값에도 출처(입력 자료와 판)와 기록한 때를 남긴다. [AD-54]
- 기준 날짜에 유효한 값이 없으면 "값 없음"으로 답한다. 오류가 아니다. 앞의 값을 끌어다 쓰지 않는다. 규칙 조건이 "값 없음"을 어떻게 평가하는지는 D8 이 정한다. [AD-55]
- 새 판에서 속성 값이 바뀌면 새 값의 시작일을 앞 값의 종료일로 넣는다. 두 값은 맞닿고, 빈 기간도 겹침도 생기지 않는다. [AD-56]
- 속성 값의 식별자와, 개체 하나의 속성 값 여럿을 돌려줄 때의 정렬 기준은 정해지지 않았다 **(결정 필요 1)**.

## 3. 관계

- 관계는 개체와 개체를 잇는다. 관계의 유형은 Pack 의 온톨로지가 정한다. [보드 PACK-01.1]
- **관계에는 방향이 있다.** 출발 개체와 도착 개체를 갖는다. [AD-29]
- 모든 관계에는 유효기간과 출처가 있다. [C 8절] [core]
- 출처는 그 관계가 어느 입력 자료의 어느 판에서 왔는지다. 모든 관계는 출처를 따라갈 수 있어야 한다. [link]
- 관계마다 기록한 때를 남긴다. 기록한 때는 엔진이 읽는 현재 시각이 아니라 밖에서 받아 넘긴 시각이다. [AD-31] [C 8절]
- 관계의 식별자는 (출발 개체, 도착 개체, 관계 유형, 출처, 시작일)에서 정해진다. [AD-37]
- 없는 개체를 가리키는 관계는 저장을 거부한다. [보드 CORE-01]
- 관계를 지우지 않는다. 끝난 관계는 종료일을 넣는다. [C 8절]

### 같은 관계와 겹침

- 출발 개체, 도착 개체, 관계 유형, 출처(입력 자료와 판)가 모두 같으면 같은 관계다. [AD-30]
- 같은 관계의 유효기간이 겹치는 저장은 거부한다. [core] 앞의 종료일과 뒤의 시작일이 같은 날인 것은 겹침이 아니다 (4절의 정의에서 따라 나온다).
- 새 판에서도 그대로인 관계는 새 행을 만들지 않는다. 처음 나타난 판의 행이 그대로 남고, 출처는 처음 나타난 판이다. [AD-30]
- 따라서 출처가 다른 관계는 두 개체와 유형이 같아도 서로 다른 관계로 저장된다. 서로 다른 입력 자료나 서로 다른 판이 같은 두 개체를 같은 유형으로, 겹치는 기간에 이으면 시점 조회는 그 둘을 모두 돌려준다. 영향 범위에서는 같은 대상을 한 번만 센다(7절).

## 4. 유효기간

- 유효기간은 시작일과 종료일이다. **시작일은 포함하고 종료일은 제외한다.** [C 8절]
- 종료일이 없으면 계속 유효하다. [C 8절]
- 시작일은 반드시 있다. 종료일이 있으면 시작일보다 뒤여야 한다. 시작일과 종료일이 같은 유효기간은 만들 수 없다. [코드]
- 단위는 날짜다. 시각은 없다. [코드]

기준 날짜 d 에 유효하다는 것은 다음과 같다. [코드]

```
시작일 <= d  그리고  (종료일이 없다  또는  d < 종료일)
```

## 5. 시점 조회

- 관계를 읽는 모든 조회는 기준 날짜를 받는다. 기준 날짜 없이 "지금 유효한 것"을 암묵적으로 읽는 조회를 만들지 않는다. 관계 기본 조회(보드 CORE-02)도 기준 날짜가 필수다. 유효기간과 무관하게 전부 읽는 조회는 v1.0 에 없다. [C 8절] [AD-32]
- **조회 시점**은 사용자가 화면과 API 에서 고르는 값이고, **기준 날짜**는 엔진이 인자로 받는 값이다. 값은 같고 층마다 이름이 다르다. [AD-50]
- 엔진 안에는 기준 날짜의 기본값이 없다. 조회 시점이 빠진 요청은 API 층에서 한 번만 오늘로 정해 기준 날짜로 넘기고, 응답에 어느 날짜로 답했는지 담는다. [core] [api]
- 오늘은 설치 설정의 시간대에서의 날짜다. 설정에 적지 않으면 Asia/Seoul 이다. 서버 운영체제의 시간대에 기대지 않는다. [AD-40]
- 시점 조회는 개체 식별자와 기준 날짜를 받아, 그 날짜에 유효한 관계를 개체가 출발 쪽이든 도착 쪽이든 모두 돌려준다. [보드 CORE-03] [AD-29]
- 날짜 형식이 틀리면 거부한다. [보드 CORE-03]
- 과거, 현재, 미래의 어느 날짜든 기준 날짜가 될 수 있다. [core]
- 조회는 유효기간만으로 답한다. 나중에 들어온 판이 과거의 유효기간을 고치면 같은 과거 기준 날짜의 답이 달라질 수 있다. 언제 어느 판에서 바뀌었는지는 기록한 때와 출처로 따라간다. "그때 알던 대로" 답하는 조회는 v1.0 에 없다. [AD-31]

### 결과의 순서

다음 차례로 정렬한다. [AD-38] [C 8절]

1. 관계 유형 (이름의 글자 코드 순)
2. 상대 개체의 식별자
3. 관계의 식별자

### 예시

개체 가 에 관계가 셋 있다. 모두 같은 관계 유형이고 가 가 출발 개체다.

| 관계 | 출발 → 도착 | 시작일 | 종료일 |
|---|---|---|---|
| R1 | 가 → 나 | 2026-03-01 | 2026-06-01 |
| R2 | 가 → 다 | 2026-06-01 | 없음 |
| R3 | 가 → 라 | 2026-01-01 | 2026-03-01 |

기준 날짜별로 개체 가 의 시점 조회가 돌려주는 관계는 다음과 같다.

| 기준 날짜 | 돌려주는 관계 | 까닭 |
|---|---|---|
| 2025-12-31 | 없음 (빈 목록) | 어느 관계도 아직 시작하지 않았다 |
| 2026-01-01 | R3 | R3 의 시작일 당일. 시작일은 포함한다 |
| 2026-02-28 | R3 | R3 의 종료일 전날 |
| 2026-03-01 | R1 | R3 는 종료일 당일이라 빠진다. R1 은 시작일 당일이라 들어온다 |
| 2026-05-31 | R1 | R1 의 종료일 전날 |
| 2026-06-01 | R2 | R1 은 종료일 당일이라 빠진다. R2 가 시작한다 |
| 2030-01-01 | R2 | 종료일이 없으면 계속 유효하다 |

개체 나 의 시점 조회도 기준 날짜가 2026-03-01 이면 R1 을 돌려준다. 나 는 R1 의 도착 쪽이다.

경계 날짜(시작일 당일, 종료일 전날, 종료일 당일)의 시험은 반드시 둔다. [core]

## 6. 판과 변동

- 판은 입력 자료 하나의 한 차례 분량이다. 입력 자료마다 판이 따로 쌓인다. 조치에 붙는 "근거 조항의 판"도 그 조항이 들어 있는 입력 자료의 판이다. [AD-41]
- 판을 투입할 때 적용일을 함께 받는다. 입력 파일은 CSV 또는 엑셀이다. [AD-42] [AD-84]
- 새 판의 행은 Pack 의 매핑 정의에 따라 개체, 속성 값, 관계로 바뀌고 유효기간과 출처가 붙는다. [link]
- 유효기간의 시작일과 종료일은 매핑이 지정한 입력 열에서 읽는다. 지정이 없으면 시작일은 판의 적용일이다. [AD-42]
- 판 비교는 같은 입력 자료의 새 판과 바로 앞 판을 항목 단위로 비교해 추가, 변경, 삭제를 낸다. 앞 판이 없으면 전부 추가로 본다. [link] [보드 LINK-04] [AD-41]
- 항목은 행이다. 매핑 정의가 입력 자료마다 행을 가려내는 키 열(하나 또는 여럿)을 정한다. 형식은 D6 이 정한다. [AD-57]
  - 키가 새 판에만 있으면 추가, 앞 판에만 있으면 삭제다.
  - 키가 같고 키 밖의 열 값이 하나라도 다르면 변경이다.
  - 행의 순서만 바뀐 것은 변동이 아니다.
- 판 비교의 결과 순서는 고정한다. [link]
- 새 판에서 사라진 관계는 지우지 않고 새 판의 적용일을 종료일로 넣어 끝낸다. [link] [AD-42]
- 같은 파일을 두 번 넣은 결과와 한 번 넣은 결과는 같다. [link]
- 변동은 판 비교에서 나온 바뀐 항목이다. link 는 바뀐 항목을 변동 이벤트로 저장한다. [보드 LINK-05] [AD-44]
- **변동 대상**은 바뀐 항목(행)이 매핑을 거쳐 만든 모든 개체다. 행에 참조로만 등장한 개체(관계의 상대편으로만 나온 개체)도 변동 대상이다. [AD-43] [AD-59]
  - 추가된 행: 새 판에서 그 행이 만든 모든 개체.
  - 삭제된 행: 앞 판에서 그 행이 만든 모든 개체.
  - 변경된 행: 앞 판과 새 판에서 그 행이 만든 개체를 합친 것. [AD-58]
- 변동 이벤트 하나는 바뀐 항목 하나이고, 변동 대상은 여럿일 수 있다. [AD-58]
- **입력 자료의 첫 판은 변동 이벤트를 만들지 않는다.** 처음 자료를 싣는 것이지 무엇이 바뀐 것이 아니다. 변동은 둘째 판부터 앞 판과 비교해 만든다. [AD-148]
- **같은 입력 자료의 새 판의 적용일은 바로 앞 판의 적용일보다 하루 이상 뒤여야 한다.** 같거나 앞서면 투입을 거부한다. 서로 다른 입력 자료 사이에는 제한이 없다. [AD-149]
- 파일의 내용이 바로 앞 판과 같으면 새 판을 만들지 않는다. [AD-155]
- 판 하나의 투입은 전부 되거나 전부 안 된다. 한 번 받아들인 판은 다시 처리하지 않는다. [AD-164]
- 행이 변경인지는 매핑이 쓰는 열의 값으로 판정한다. 값은 읽은 뒤의 표기로 견준다. [AD-156]
- 한 판 안에서 항목의 키가 겹치는 행은 모두 건너뛴다. 앞 판에 그 키의 항목이 있었다면 그대로 이어 둔다. [AD-157]
- 변동 대상 가운데 **주 개체**는 그 행이 나타내는 개체 하나다. 매핑이 적는다. 조치의 근거 조항이 된다. [AD-120]
- 새 판에서 행이 없어지면 그 행이 넣었던 관계와 속성 값을 새 판의 적용일로 끝낸다. [AD-42] [AD-121]
- 항목의 키는 키 열의 값을 식별자와 같은 규칙으로 이은 글자다. [AD-122]

## 7. 영향

- 영향 범위 계산은 변동 대상(하나 또는 여럿), 기준 날짜(하나 또는 여럿), 관계 유형마다의 영향 방향, 최대 깊이를 받는다. [AD-115] [AD-66]
- 변동 대상에서 기준 날짜에 유효한 관계를 따라가며 영향받는 대상을 찾는다. 날짜가 여럿이면 날짜마다 따라가 합친다. [보드 CORE-04] [core]
- **변동 이벤트의 영향 범위는 두 날짜로 본다.** 판의 적용일 전날의 관계로 한 번, 적용일의 관계로 한 번 따라가 합친다. 새 판에서 사라진 관계는 적용일에 끝나므로 적용일만 보면 없어진 것의 영향을 찾지 못하기 때문이다. core 가 기준 날짜를 여럿 받아 합친다. 같은 대상에 두 날짜 모두 닿으면 더 짧은 경로를, 길이가 같으면 더 늦은 날짜의 경로를 남긴다. [AD-100] [AD-115] [AD-116]
- 변동 이벤트의 영향 범위와 조치는 판을 투입한 직후에 한 번 계산해 저장한다. [AD-119]
- **영향 범위는 변동 이벤트마다 하나다.** 한 이벤트의 변동 대상 전부에서 함께 출발해 영향 범위 하나를 만든다. core 는 변동 이벤트를 모르므로 출발 개체의 모음을 인자로 받는다. [AD-64] [core]
- **따라가는 방향은 Pack 이 정한다.** 온톨로지가 관계 유형마다 영향이 퍼지는 방향을 적는다: 출발에서 도착으로, 도착에서 출발로, 양쪽, 퍼지지 않음. 엔진은 그 값만 읽는다. 형식은 D6 이 정한다. [AD-33]
- **변동 대상 자신은 영향 대상에 넣지 않는다.** 영향 대상은 변동 대상에서 관계를 하나 이상 건너 도달한 다른 개체다. 관계가 돌아와 변동 대상에 다시 닿아도 넣지 않는다. 변동 대상이 여럿이면 그 전부를 뺀다. [AD-34] [AD-64]
- 돌려주는 것은 영향 대상 목록, 개체 유형별 수, 깊이별 수다. 같은 대상은 한 번만 세고, 두 수의 합계는 각각 영향 대상 목록의 길이와 같다. 유형별 수는 유형 이름 순, 깊이별 수는 깊이 순으로 정렬한다. [보드 CORE-04] [AD-63]
- 영향 대상의 깊이는 가장 가까운 변동 대상에서 건넌 관계의 수다. [AD-35] [AD-64]
- 영향 대상마다 근거 경로가 붙는다. 어느 변동 대상에서 시작해 어떤 관계를 따라 도달했는지다. 근거 없는 결과를 만들지 않는다. [C 8절] [보드 CORE-04.1] [AD-64]
- 근거 경로가 여럿이면 가장 짧은 것을 남긴다. 길이가 같으면 두 경로의 관계 식별자를 변동 대상 쪽부터 차례로 비교해, 처음 다른 자리에서 식별자가 앞선 경로를 남긴다. [core] [AD-36]
- 관계가 돌아오는 구조에서도 계산은 끝나야 한다. 같은 대상은 한 번만 센다. [core]
- 결과의 순서는 고정한다. 재귀 질의의 결과를 정렬 없이 내보내지 않는다. [core] [규칙 engine]
- 영향 대상 목록은 깊이, 개체 유형(이름의 글자 코드 순), 개체 식별자 차례로 정렬한다. [AD-61]
- 따라가다가 영향 방향을 넘겨받지 못한 관계 유형의 관계를 만나면 어느 유형인지 알리며 계산을 멈춘다. 한계 표시를 정하려고 최대 깊이 너머를 따라갈 때 만나도 같다. 너머는 날짜마다 합친 결과에 없는 대상을 찾을 때까지만 따라가므로, 그보다 먼 곳의 관계는 만나지 않는다. [AD-123]
- 출발 개체는 모두 같은 Pack 의 것이어야 한다. 서로 다른 Pack 의 개체를 함께 넘기면 거부한다. [AD-74]

### 최대 깊이

- 변동 대상에서 관계 하나를 건넌 대상이 깊이 1 이다. [AD-35]
- core 는 최대 깊이를 항상 인자로 받는다. 엔진 안에 기본값이 없다. 요청에 값이 없으면 API 층이 Pack 에 적힌 기본값을 넣어 넘긴다. 형식은 D6 이 정한다. [AD-35]
- 최대 깊이까지 찾은 대상은 항상 돌려준다. "한계에서 멈췄다"는 표시는 최대 깊이에서 한 단계를 더 따라가면 아직 찾지 못한 대상에 실제로 닿을 때만 켠다. 남은 관계가 이미 찾은 대상이나 변동 대상으로만 이어지면 켜지 않는다. 표시가 켜져 있으면 깊이를 늘릴 때 결과가 늘어난다는 뜻이다. [core] [AD-35] [AD-62]
- 날짜가 여럿이면 표시는 합친 결과를 기준으로 켠다. 어느 날짜에서든 최대 깊이 너머에 합친 결과에 없는 대상이 하나라도 있으면 켠다. 한 날짜의 한 단계 너머가 다른 날짜에서 이미 찾은 대상이면 그 대상을 지나 더 따라가 본다. 이때 "깊이를 늘리면"은 한 단계가 아니라 충분히 늘린다는 뜻이다. [AD-117]

### 예시

관계 유형은 하나이고, 이 유형의 영향 방향은 "출발에서 도착으로"다. 모두 기준 날짜에 유효하다.

| 관계 | 출발 → 도착 |
|---|---|
| R1 | 가 → 나 |
| R2 | 나 → 다 |
| R3 | 가 → 다 |
| R4 | 다 → 가 |
| R5 | 라 → 가 |

변동 대상이 가 이고 최대 깊이가 3 일 때:

| 영향 대상 | 깊이 | 근거 경로 | 까닭 |
|---|---|---|---|
| 나 | 1 | R1 | |
| 다 | 1 | R3 | R1, R2 를 거치는 경로(길이 2)도 있지만 가장 짧은 것을 남긴다 |

- 가 는 R4 로 다시 닿지만 변동 대상 자신이라 넣지 않는다.
- 라 는 넣지 않는다. R5 는 라 에서 가 로 향하고, 영향은 출발에서 도착으로만 퍼진다.
- 계산은 끝난다. 한 번 찾은 대상은 다시 따라가지 않는다.

돌려주는 수는 개체 유형별 수(나 와 다 의 유형에 따라)와 깊이별 수(깊이 1: 2)다. 목록의 순서는 깊이가 같으므로 개체 유형, 개체 식별자 순이다.

같은 자료에서 최대 깊이가 1 이면 결과는 나, 다 로 같다. 깊이 1 에서 따라갈 관계(R2, R4)가 남아 있지만 닿는 곳이 이미 찾은 대상(다)과 변동 대상(가)뿐이므로 "한계에서 멈췄다"는 표시는 켜지 않는다.

관계 R6 (다 → 마)를 더하면, 최대 깊이 1 일 때 결과는 여전히 나, 다 이고 표시가 켜진다. 한 단계를 더 따라가면 아직 찾지 못한 마 에 닿기 때문이다. 최대 깊이 2 이면 마 (깊이 2, 근거 경로 R3, R6)가 더해지고 표시는 꺼진다.

변동 대상이 가 와 나 둘이면(한 변동 이벤트), 영향 대상은 다 하나다. 나 는 변동 대상이라 빠진다. 다 에 이르는 길이 1 의 경로는 R3 (가 에서)와 R2 (나 에서) 둘이고, 관계 식별자가 앞선 R2 를 남긴다. 근거 경로에는 시작한 변동 대상이 나 라고 적힌다.

## 8. 조치

- 규칙 실행은 영향 범위와 Pack 의 규칙 목록을 받아 해당하는 규칙을 고른다. 규칙의 내용은 Pack 에 있다. [rules] [보드 RULE-01]
- 규칙은 조치의 대상을 영향 대상과 변동 대상 가운데 고를 수 있다. 변동 대상을 대상으로 하는 조치는 근거 경로가 비어 있다. [AD-102]
- 조치는 해당 규칙과 영향 대상에서 만든다. 조치에는 근거 규칙, 근거 조항과 그 판, 대상, 기한, 우선순위가 붙는다. 근거 조항은 변동이 생긴 행의 주 개체이고, 판은 그 변동이 나온 입력 자료의 새 판이다. [rules] [보드 RULE-02] [AD-120]
- 근거 조항이 없는 조치는 만들지 않는다. [C 8절] [rules]
- 기한은 변동이 나온 판의 적용일에 규칙이 적은 일수를 더한 날짜다. 현재 시각을 읽지 않는다. [AD-99]
- 같은 입력에는 같은 조치가 같은 순서로 나온다. 평가 순서는 D8 이 정한다. 우선순위는 수가 작을수록 먼저고, 같으면 규칙 번호 순이다. [rules] [AD-103]
- 규칙 하나가 평가에 실패해도 나머지는 계속 평가하고, 실패한 규칙과 이유를 결과에 담는다. [rules]
- 변동 이벤트, 규칙, 대상이 모두 같으면 같은 조치다. 같은 변동 이벤트로 규칙을 다시 실행해도 이미 있는 조치는 새로 만들지 않고 그대로 둔다. 다른 변동 이벤트가 같은 대상에 같은 규칙을 걸면 조치가 새로 생긴다. 조치의 식별자도 이 세 가지에서 정해진다. [AD-47] [AD-60]

### 조치의 상태

상태는 대기, 확정, 보류 세 가지다. [AD-47]

```
대기 ──▶ 확정
대기 ──▶ 보류 ──▶ 확정
```

- 조치는 대기로 만들어진다.
- 담당자가 대기를 확정하거나 보류한다. 보류한 조치는 나중에 확정할 수 있다.
- 확정은 되돌릴 수 없다. 이미 확정된 조치는 다시 확정할 수 없다. [rules]
- 모든 변경에는 누가 언제 했는지 이력이 남는다. [rules] [보드 RULE-03]

## 9. 결정 필요

2026-11-20 의 두 차례 결정으로 앞 초안의 질문은 모두 닫혔다 (AD-29 ~ AD-64). 남은 것이다.

1. (닫힘, AD-335: D5 3절대로) **속성 값의 식별자와 정렬.** 겹침을 출처와 무관하게 거부하므로 [AD-53] 속성 값은 (개체, 속성, 시작일)로 하나로 정해진다. 식별자를 이것으로 하는가? 개체 하나의 속성 값 여럿을 돌려줄 때 속성 이름 순으로 정렬하는가? D5 에서 정해도 된다.
2. (닫힘, AD-307: 규칙을 그대로 확정) **넓게 잡히는 영향 범위.** 참조로만 등장한 개체도 변동 대상으로 하기로 했다 [AD-59]. 여러 행이 함께 가리키는 개체가 변동 대상이 되면 그 개체에 이어진 전체가 영향 범위에 들 수 있다. 예시 Pack 의 검증 질문(D4)의 정답을 정할 때 이 규칙으로 계산한 결과가 기대와 맞는지 확인이 필요하다.
3. (닫힘, AD-308: 둘 다 주고 출처와 함께 두 줄로) **겹쳐 저장된 관계.** 출처가 다르면 같은 두 개체, 같은 유형의 관계가 겹치는 기간에 둘 다 저장된다 [AD-30]. 시점 조회는 둘을 모두 돌려준다. 화면과 API 가 이것을 한 줄로 합쳐 보여 주는가, 출처와 함께 두 줄로 보여 주는가? D7 에서 정한다.
