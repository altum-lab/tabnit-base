## 1. Pack 이란

- Pack 은 업무 영역 하나의 지식 묶음이다: 온톨로지, 제약, 매핑, 규칙, 검증 질문. [pack] [C 1절]
- 업무 영역 지식은 코드가 아니라 Pack 에 둔다. 엔진은 처음 보는 Pack 이 들어와도 코드를 고치지 않고 동작해야 한다. [AD-01]
- Pack 적재는 정의만 저장한다. 개체와 관계는 항상 입력 자료가 link 의 매핑을 거쳐 들어온다. [AD-45]
- Pack 은 서로 독립이다. 한 Pack 의 정의가 다른 Pack 의 유형을 가리키지 않는다. [AD-74]
- 저장소에는 예시 Pack 둘(제조 안전, 퇴직연금)과 시험용 Pack 하나(test-mini)가 있다. 모두 가상 데이터만 담는다. [AD-49] [packs]

## 2. 폴더 구조

Pack 은 폴더 하나다. (제안)

```
packs/<Pack 식별자>/
  pack.ttl           Pack 자신의 정보 (식별자, 이름, 최대 깊이의 기본값)
  ontology.ttl       온톨로지: 개체 유형, 관계 유형, 속성
  constraints.ttl    제약 (SHACL)
  mappings/          매핑 정의 (Turtle). 입력 자료 하나에 파일 하나     [AD-90]
  rules/             규칙. 형식은 D8 이 정한다                        [AD-85]
  questions/         검증 질문과 정답. 형식은 D4 가 정한다            [AD-85]
  data/              예시 입력 파일 (CSV, xlsx). 없어도 된다           [AD-45]
```

- 정의 파일(Pack 정보, 온톨로지, 매핑)은 RDF 의 Turtle 형식으로 적는다. 제약은 SHACL 로 적는다. [AD-83] [AD-90]
- 정의 파일은 Apache Jena 로 읽는다. 이 라이브러리는 pack 모듈 안에서만 쓰고, 다른 모듈은 pack 이 만든 내부 모델만 본다. [AD-87] [AD-15]
- 파일은 UTF-8 이다. (제안)
- Pack 식별자는 폴더 이름과 `pack.ttl` 에 적힌 식별자가 같아야 한다. 다르면 읽지 않는다. (제안)
- Pack 식별자는 개체의 식별자와 정의의 주소에 들어가므로 한 번 정하면 바꾸지 않는다. [D5 1절] [AD-89]

## 3. 어휘와 주소

정의 파일은 표준 어휘와 이 제품의 어휘를 함께 쓴다.

| 접두어 | 주소 | 쓰임 |
|---|---|---|
| `rdf:`, `rdfs:` | RDF 와 RDF Schema 의 표준 주소 | 유형, 이름표, 하위 유형 |
| `owl:` | OWL 의 표준 주소 | 개체 유형, 관계 유형, 속성을 가름 |
| `xsd:` | XML Schema 자료형의 표준 주소 | 속성의 형식 |
| `sh:` | SHACL 의 표준 주소 | 제약 |
| `tabnit:` | `urn:tabnit:vocab:` | 이 제품의 어휘. 영향 방향, 표시 이름, 최대 깊이, 매핑 [AD-89] |
| (Pack 마다) | `urn:tabnit:pack:<Pack 식별자>:` | 그 Pack 의 유형, 속성, 매핑 [AD-89] |

- Pack 의 정의는 모두 그 Pack 의 주소로 시작한다. 실제 인터넷 주소가 아니다. 설치한 곳에서 밖을 가리키지 않는다. [AD-89]
- 아래 예시의 `ex:` 는 그 Pack 의 주소를 줄여 쓴 것이다.

### 엔진이 읽는 것과 거부하는 것

- 엔진이 읽는 것은 이 문서에 적힌 항목뿐이다. [AD-88]
- 이 문서에 없는 문장(다른 어휘, 역관계, 하위 관계 유형, 그 밖의 OWL 추론 규칙)이 정의 파일에 있으면 파일과 위치를 알리며 Pack 을 읽지 않는다. 무시하고 넘어가지 않는다. [AD-88]
- 추론은 하위 유형(5절) 하나만 한다. [AD-88]

## 4. pack.ttl — Pack 자신의 정보

```turtle
<urn:tabnit:pack:pack-id:> a tabnit:Pack ;
   tabnit:packId "pack-id" ;
   rdfs:label "Pack 의 이름" ;
   tabnit:defaultMaxDepth 3 .
```

| 항목 | 반드시 | 뜻 | 근거 |
|---|---|---|---|
| `tabnit:packId` | 예 | Pack 식별자. 폴더 이름과 같다. 영어 소문자로 시작하고 영어 소문자, 숫자, 붙임표(-)만 쓴다 | [D5 1절] [AD-134] |
| `rdfs:label` | 예 | 사람이 읽는 이름. 적는 법은 5절 "이름표" | [AD-131] |
| `tabnit:defaultMaxDepth` | 예 | 영향 범위의 최대 깊이 기본값. 1 이상의 정수 | [AD-35] |

## 5. ontology.ttl — 온톨로지

온톨로지는 개체 유형, 관계 유형, 속성을 정의한다. [보드 PACK-01.1] 개체 유형은 하나 이상 있어야 한다. 관계 유형이나 속성은 없어도 된다. [AD-133]

### 이름

- 개체 유형, 관계 유형, 속성의 **이름**은 식별자와 저장소의 열(`entity_type`, `relation_type`, `attribute_name`)에 들어가는 글자다. [D5 3절]
- 이름은 정의의 주소에서 Pack 의 주소 뒤에 오는 부분이다. `urn:tabnit:pack:pack-id:TypeA` 의 이름은 `TypeA` 다. 한글 이름도 그대로 쓴다. [AD-89]
- **이름은 조합형(유니코드 NFC)으로 적는다.** 조합형이 아니면 어느 정의인지 알리며 Pack 을 읽지 않는다. 엔진은 이름의 글자를 바꾸지 않는다. 그 밖의 글자는 막지 않는다. [AD-127]
- `rdfs:label` 은 화면에 보이는 글자이고 이름이 아니다.
- 한 Pack 안에서 이름은 겹치지 않는다. 이름은 한 번 정하면 바꾸지 않는다. [AD-95]
- 코드에 특정 Pack 의 이름을 넣지 않는다. [C 8절] Pack 을 만들면 그 이름을 `tools/pack-terms.txt` 에 더해 일반성 검사가 찾게 한다.

### 이름표

```turtle
ex:TypeA rdfs:label "유형 가" , "Type A"@en .
```

- 정의마다 **언어 표시 없는 이름표를 반드시 하나** 적는다. 기본 이름표다. v1.0 의 화면과 API 는 이것을 보여 준다. [AD-131]
- 그 위에 언어 표시가 붙은 이름표를 언어마다 하나씩 더 적을 수 있다. 같은 언어가 둘이면 Pack 을 읽지 않는다. 언어 표시는 대소문자를 가리지 않고 소문자로 저장한다 (`ko-KR` 과 `ko-kr` 은 같은 언어다). [AD-131]
- 언어별 이름표는 저장하고 pack 의 공개 API 로 읽을 수 있다. 언어를 골라 보여 주는 화면은 v1.0 범위 밖이다. [AD-131]
- 이름표는 빈 글자일 수 없다. Pack 자신의 이름표(4절)도 같은 규칙이다.

### 개체 유형

```turtle
ex:TypeA a owl:Class ;
    rdfs:label "유형 가" ;
    rdfs:subClassOf ex:TypeBase ;
    tabnit:displayNameProperty ex:name .
```

| 항목 | 반드시 | 뜻 | 근거 |
|---|---|---|---|
| `a owl:Class` | 예 | 개체 유형이다 | 제안 |
| `rdfs:label` | 예 | 화면에 보일 유형의 이름 | [AD-131] |
| `rdfs:subClassOf` | 아니오 | 상위 유형. 여럿 적을 수 있다 | [AD-88] |
| `tabnit:displayNameProperty` | 아니오 | 개체의 표시 이름으로 쓸 속성. 그 유형이나 그 상위 유형의 속성이어야 한다. 형식은 가리지 않는다. 없거나 기준 날짜에 값이 없으면 입력의 키를 보여 준다 | [AD-70] [AD-132] |

### 하위 유형

- 유형은 상위 유형을 가질 수 있고, 여럿을 가질 수 있다. [AD-88]
- **개체는 가장 구체적인 유형 하나로 저장한다.** 저장소의 `entity_type` 과 개체의 식별자에는 그 유형의 이름이 들어간다. [AD-88]
- 상위 유형에 걸린 것은 하위 유형에도 적용된다: 상위 유형이 출발이나 도착인 관계 유형, 상위 유형의 속성, 상위 유형에 건 규칙. [AD-88]
- 유형이 스스로 적은 값(예: 표시 이름 속성)이 있으면 그것을 쓴다. 없으면 상위 유형의 값을 받는다. **여러 상위 유형이 서로 다른 값을 내려주면 Pack 을 읽지 않고**, 어느 유형에서 무엇이 충돌하는지 알린다. 엔진이 임의로 고르지 않는다. [AD-88]
- 유형이 돌아와 자기 자신의 상위가 되는 정의는 거부한다. [AD-88]
- 영향 범위의 "개체 유형별 수"[AD-63]와 영향 대상 목록의 정렬[AD-61]이 구체적인 유형으로 하는지 상위 유형으로도 묶는지는 "결정 필요" 1번.

### 관계 유형

```turtle
ex:relatesTo a owl:ObjectProperty ;
    rdfs:label "관계의 이름" ;
    rdfs:domain ex:TypeA ;
    rdfs:range  ex:TypeB ;
    tabnit:impactDirection tabnit:SourceToTarget .
```

| 항목 | 반드시 | 뜻 | 근거 |
|---|---|---|---|
| `a owl:ObjectProperty` | 예 | 관계 유형이다 | 제안 |
| `rdfs:label` | 예 | 화면에 보일 이름 | 제안 |
| `rdfs:domain` | 예, 하나만 | 출발 개체의 유형 | [AD-29] [AD-91] |
| `rdfs:range` | 예, 하나만 | 도착 개체의 유형 | [AD-29] [AD-91] |
| `tabnit:impactDirection` | 예 | 영향이 퍼지는 방향. 아래 넷 가운데 하나 | [AD-33] |

| `tabnit:impactDirection` 의 값 | 뜻 |
|---|---|
| `tabnit:SourceToTarget` | 출발에서 도착으로 |
| `tabnit:TargetToSource` | 도착에서 출발로 |
| `tabnit:Both` | 양쪽 |
| `tabnit:None` | 퍼지지 않는다 |

- 출발 유형과 도착 유형은 하나씩만 적는다. 여러 유형을 묶으려면 공통 상위 유형을 만들어 그것을 적는다. [AD-91]
- 출발 개체와 도착 개체의 유형이 온톨로지와 맞지 않는 관계가 입력에 있으면(하위 유형은 맞는 것으로 본다) 그 행을 건너뛰고 행 번호와 이유를 남긴다. [AD-91] [AD-88]
- 영향 방향은 반드시 적는다. 빠지면 Pack 을 읽지 않는다. 기본값을 두지 않는다. (제안)

### 속성

```turtle
ex:name a owl:DatatypeProperty ;
    rdfs:label "속성의 이름" ;
    rdfs:domain ex:TypeA ;
    rdfs:range  xsd:string .
```

| 항목 | 반드시 | 뜻 | 근거 |
|---|---|---|---|
| `a owl:DatatypeProperty` | 예 | 속성이다 | 제안 |
| `rdfs:label` | 예 | 화면에 보일 이름 | 제안 |
| `rdfs:domain` | 예, 하나만 | 이 속성을 갖는 개체 유형. 그 하위 유형도 갖는다 | [pack] [AD-88] |
| `rdfs:range` | 예 | 값의 형식. 아래 다섯 가운데 하나 | [AD-71] |

| 형식 [AD-71] | `rdfs:range` (제안) | 저장하는 표기 (제안) |
|---|---|---|
| 글자 | `xsd:string` | 그대로 |
| 정수 | `xsd:integer` | `-12`, `0`, `340` 처럼. 자릿수 구분 기호 없이 |
| 소수 | `xsd:decimal` | `3.14` 처럼. 소수점은 마침표. 지수 표기 없이 |
| 날짜 | `xsd:date` | `2026-03-01` |
| 참·거짓 | `xsd:boolean` | `true`, `false` |

- 속성 값은 글자 열 하나에 위의 표기로 저장한다. [AD-71]
- 입력 파일의 값을 위의 표기로 바꾸는 법은 매핑이 열마다 정한다 (7절). [AD-94]

## 6. constraints.ttl — 제약

제약은 SHACL 로 적는다. [AD-83]

```turtle
ex:TypeAShape a sh:NodeShape ;
    sh:targetClass ex:TypeA ;
    sh:property [
        sh:path ex:name ;
        sh:minCount 1 ;
        sh:datatype xsd:string ;
    ] .
```

- **제약은 적재가 끝난 뒤 전체 자료에 걸어 위반을 보고한다.** 제약을 어긴 자료도 그대로 들어간다. 제약은 행을 건너뛰게 하지 않는다. [AD-92]
- 행을 건너뛰게 하는 것은 형식이 틀린 값, 온톨로지와 맞지 않는 관계, 비어 있는 키 열이다 (7절). 이것은 제약 파일이 아니라 온톨로지와 매핑에서 나온다.
- 제약 파일이 가리키는 유형과 속성은 온톨로지에 있어야 한다. 없으면 Pack 을 읽지 않는다. [보드 PACK-01.1]
- 제약을 거는 때, 기준 날짜, 지원하는 SHACL 의 범위, 위반을 보여 주는 곳은 "결정 필요" 2번.

## 7. mappings/ — 매핑

매핑은 입력 자료의 열을 개체, 속성 값, 관계로 옮기는 규칙이다. 입력 자료 하나에 매핑 정의 하나다. [보드 PACK-01.2] [AD-41]

매핑 정의는 이 제품의 어휘로 Turtle 에 적는다. [AD-90] 낱말은 아래 "담을 것" 다음의 "매핑 어휘"에 있다. [AD-139] 본보기는 시험용 Pack(`packs/test-mini/mappings/`)이다.

### 담을 것

| 담을 것 | 뜻 | 근거 |
|---|---|---|
| 입력 자료의 식별자 | 판이 쌓이는 단위. 출처의 `input_source_id` 가 된다 | [AD-41] [D5 1절] |
| 파일의 종류 | CSV 인지 xlsx 인지. xlsx 면 어느 시트인지 | [AD-84] |
| 반드시 있어야 하는 열 | 없으면 파일 전체를 거부한다 | [link] |
| 항목의 키 열 | 판 비교에서 행을 같은 항목으로 알아보는 열. 하나 또는 여럿. 값을 적힌 차례로, 식별자와 같은 규칙으로 이은 글자가 항목의 키다 | [AD-57] [AD-122] |
| 행의 주 개체 | 이 행이 나타내는 개체 하나. 반드시 적는다. 이 행에서 나온 변동의 근거 조항이 된다. 관계만 담은 자료는 관계의 한쪽 끝을 적는다 | [AD-120] |
| 행이 만드는 개체 | 개체 유형과, 입력의 키가 되는 열 | [AD-37] |
| 개체의 속성 값 | 어느 열이 어느 속성의 값인지 | [AD-39] |
| 행이 만드는 관계 | 관계 유형, 출발 개체, 도착 개체 | [AD-29] |
| 유효기간의 열 | 시작일과 종료일을 읽을 열. 지정하지 않으면 시작일은 판의 적용일이다 | [AD-42] |
| 열마다 값을 읽는 법 | 날짜의 모양, 자릿수 구분 기호, 참과 거짓으로 볼 글자 | [AD-94] |

- 매핑이 가리키는 유형과 속성은 온톨로지에 있어야 한다. 없으면 Pack 을 읽지 않는다. [보드 PACK-01.2]
- 매핑은 Pack 에 있다. 특정 파일의 열 이름을 코드에 넣지 않는다. [link]
- 행 하나가 개체 여럿과 관계 여럿을 만들 수 있다. 행이 만든 모든 개체가 그 행의 변동 대상이 된다. [AD-43]
- **속성 하나는 매핑 하나만 넣는다.** 두 매핑이 같은 개체 유형(매핑에 적힌 그대로)의 같은 속성을 적으면 Pack 을 읽지 않는다. 여러 입력 자료가 같은 개체를 가리킬 수는 있다. 그때 속성은 한 자료만 넣고 나머지는 키로 가리키기만 한다. 서로 다른 하위 유형에 같은 속성을 넣는 것은 받는다. [AD-137]

### 매핑 어휘

시험용 Pack 의 매핑을 적어 보면서 정한 낱말이다. [AD-139]

```turtle
ex:매핑-이름 a tabnit:Mapping ;
    tabnit:inputSourceId "source-id" ;
    tabnit:fileFormat tabnit:Csv ;
    tabnit:requiredColumns ( "열1" "열2" ) ;
    tabnit:itemKeyColumns ( "열1" ) ;
    tabnit:primaryEntity [ tabnit:entityType ex:TypeA ; tabnit:keyColumn "열1" ] ;
    tabnit:entity [
        tabnit:entityType ex:TypeA ;
        tabnit:keyColumn "열1" ;
        tabnit:attribute [ tabnit:property ex:name ; tabnit:column "열2" ]
    ] ;
    tabnit:relation [
        tabnit:relationType ex:relatesTo ;
        tabnit:sourceEntity [ tabnit:entityType ex:TypeA ; tabnit:keyColumn "열1" ] ;
        tabnit:targetEntity [ tabnit:entityType ex:TypeB ; tabnit:keyColumn "열3" ]
    ] .
```

| 낱말 | 뜻 |
|---|---|
| `tabnit:Mapping` | 매핑 정의 하나. 입력 자료 하나에 하나다 |
| `tabnit:inputSourceId` | 입력 자료의 식별자. 영어 소문자로 시작하고 영어 소문자, 숫자, 붙임표(-)만 쓴다 [AD-145] |
| `tabnit:fileFormat` | `tabnit:Csv` 또는 `tabnit:Xlsx`. 엑셀이면 `tabnit:sheetName` 으로 시트를 적는다 |
| `tabnit:requiredColumns` | 반드시 있어야 하는 열의 목록 |
| `tabnit:itemKeyColumns` | 항목의 키 열의 목록. 적힌 차례대로 이어 붙여 항목의 키를 만든다 |
| `tabnit:primaryEntity` | 행의 주 개체. 유형과 키 열로 가리킨다. 반드시 하나 적는다. 없으면 Pack 을 읽지 않는다 [AD-120] |
| `tabnit:entity` | 행이 만드는 개체. 여럿 적을 수 있다 |
| `tabnit:entityType`, `tabnit:keyColumn` | 개체 유형과, 입력의 키가 되는 열 |
| `tabnit:attribute` | 속성 값 하나. `tabnit:property` (속성)와 `tabnit:column` (열) |
| `tabnit:relation` | 행이 만드는 관계. 여럿 적을 수 있다 |
| `tabnit:relationType`, `tabnit:sourceEntity`, `tabnit:targetEntity` | 관계 유형과 출발 개체, 도착 개체. 개체는 유형과 키 열로 가리킨다 |
| `tabnit:validFromColumn`, `tabnit:validToColumn` | 유효기간의 시작일과 종료일을 읽을 열. 관계와 속성 값에 적을 수 있다. 없으면 시작일은 판의 적용일이다 |
| `tabnit:datePattern` | 날짜 속성의 열의 모양 (예: `yyyy.M.d`). 적는 법은 아래 "값을 읽는 법" [AD-144] |
| `tabnit:defaultDatePattern` | 매핑에 하나 적는 날짜의 기본 모양. 유효기간의 열과, 모양을 따로 적지 않은 날짜 속성의 열을 이 모양으로 읽는다 [AD-143] |
| `tabnit:groupingSeparator` | 수 열의 자릿수 구분 기호. 글자 하나 (예: `,`). 숫자와 부호, 소수 속성의 마침표는 쓸 수 없다 [AD-178] |
| `tabnit:trueValue`, `tabnit:falseValue` | 참·거짓 열에서 참과 거짓으로 볼 글자 |

- **차례가 뜻을 갖는 목록은 Turtle 의 목록 `( ... )` 으로 적는다.** 값을 쉼표로 늘어놓으면 차례가 없어, 항목의 키가 읽을 때마다 달라질 수 있다. [AD-139]
- **관계의 끝에 적힌 개체는 없으면 만든다.** 속성 없이 식별자만 가진 개체가 된다. 속성은 다른 입력 자료가 넣을 수 있다. 이것이 "참조로만 만들어진 개체"다. [AD-59] [AD-139]
- 판을 투입한 결과에는 그 투입으로 참조로만 만들어진 개체의 목록이, 어느 행이 가리켰는지와 함께 담긴다. 오타인지 아직 들어오지 않은 자료인지는 담당자가 본다. 투입을 막지 않는다. [AD-138]
- 관계의 끝을 가리키는 열이 빈 칸이면 그 관계를 만들지 않는다. [AD-94]
- 행이 만드는 개체의 유형은 매핑에 고정으로 적는다. 열의 값에 따라 유형을 고르는 낱말은 v1.0 에 두지 않는다. 한 파일에 여러 유형이 섞여 있으면 유형마다 입력 자료를 나눈다. [AD-135]

### 매핑의 검증

Pack 을 적재할 때 매핑이 온톨로지와 맞는지 본다. 틀리면 파일(`mappings/파일이름`)과 매핑의 이름, 틀린 항목을 알리며 Pack 을 읽지 않는다. [AD-140]

- 반드시 적는 것: 입력 자료의 식별자, 파일의 종류, 항목의 키 열(하나 이상, 겹치지 않게), 행의 주 개체(하나). [AD-57] [AD-120]
- 입력 자료의 식별자는 한 Pack 안에서 겹치지 않는다. [AD-41]
- 매핑이 가리키는 개체 유형, 속성, 관계 유형은 온톨로지에 있어야 한다. [보드 PACK-01.2]
- 속성 하나는 매핑 하나만 넣는다. [AD-137]
- D6 에 없는 문장은 매핑의 안쪽 정의에 있어도 거부한다. [AD-88]
- 아래도 확정한 규칙이다. [AD-147]
  - 엑셀 매핑은 시트를 반드시 적고, CSV 매핑은 시트를 적지 않는다.
  - 반드시 있어야 하는 열의 목록은 적지 않아도 된다.
  - 행의 주 개체는 그 행이 만드는 개체(`tabnit:entity` 나 관계의 끝) 가운데 하나여야 한다.
  - 속성은 그 개체 유형이나 그 상위 유형의 것이어야 한다.
  - 관계의 끝에 적은 유형은 관계 유형의 출발·도착 유형이거나 그 하위 유형이어야 한다.
  - 값을 읽는 법은 속성의 형식과 맞아야 한다: 날짜의 모양은 날짜 속성에만, 자릿수 구분 기호는 수 속성에만, 참과 거짓으로 볼 글자는 참·거짓 속성에만 둘을 함께.
- 자릿수 구분 기호는 글자 하나다. 숫자, 더하기·빼기 부호, 소수 속성에서의 마침표는 거부한다. 부호에는 ASCII 가 아닌 빼기·더하기·줄표 글자와 수학 기호도 든다 (구현하면서 넓혀 읽은 것). [AD-178]
  - 한 매핑 안에서 같은 개체(유형과 키 열), 같은 속성, 같은 관계를 두 번 적으면 거부한다.
  - `mappings/` 폴더에서 이름이 `.ttl` 로 끝나는 파일만 읽는다. 파일 하나에 매핑은 하나이고, 매핑에는 이름(주소)을 붙인다.
  - 안쪽 정의는 쓰는 곳마다 `[ … ]` 로 따로 적는다. 이름 붙인 주소로 적거나 한 안쪽 정의를 두 곳에서 가리키는 것은 받지 않는다.
  - 글자 값에 NUL 글자가 있으면 거부한다. 저장소가 받지 않는다. 이름표도 같다.
- 고친 Pack 을 다시 적재할 때 매핑을 더하는 것은 받는다. [AD-95] 판이 하나도 들어오지 않은 입력 자료의 매핑은 바꾸거나 지울 수 있고, 판이 하나라도 들어온 입력 자료의 매핑은 바꾸거나 지울 수 없다. 바꾸려면 새 식별자의 입력 자료를 더한다. [AD-142]
- **지금의 구현은 매핑을 바꾸거나 지우는 것을 모두 거부한다.** 판이 있는지 답하는 link 의 공개 API 가 아직 없기 때문이다. [AD-142]

### 값을 읽는 법

- 매핑이 열마다 값의 모양을 적는다 (예: 날짜는 `yyyy.M.d`, 자릿수 구분 기호 있음, 참은 `예`). 엔진은 적힌 모양으로만 읽는다. 추측하지 않는다. [AD-94]
- 모양을 적지 않은 열은 5절의 표기만 받는다. [AD-94]
- **날짜의 모양.** 날짜 속성의 열에는 `tabnit:datePattern` 으로 모양을 적는다. 매핑에 `tabnit:defaultDatePattern` 을 적으면 유효기간의 열과, 모양을 따로 적지 않은 날짜 속성의 열을 그 모양으로 읽는다. 둘 다 없으면 `2026-03-01` 의 표기만 받는다. [AD-143]
- 날짜의 모양에는 연(`y`), 월(`M`), 일(`d`)을 숫자로 적는 글자와 구분 글자(마침표, 붙임표, 빗금, 빈칸, 작은따옴표로 감싼 글자)만 쓴다. 연, 월, 일이 모두 한 번씩 있어야 한다. 예: `yyyy.M.d`, `yyyy-MM-dd`, `yyyy'년' M'월' d'일'`. 달의 이름(`MMM`), 요일, 시·분, 오전·오후는 받지 않는다. [AD-144]
- 그 위의 규칙이다. [AD-165]
  - 연은 네 자리 `yyyy` 만 받는다. 두 자리 연도(`yy`)는 어느 세기인지 정해져 있지 않아 받지 않는다.
  - 모양의 앞뒤에 빈칸이 있으면 거부한다.
  - 그 모양으로 적은 날짜를 다시 읽을 수 없으면 거부한다. 구분 글자 없이 이어 붙일 때는 월과 일을 두 자리로 적어야 읽힌다 (`yyyyMMdd` 는 받고 `yyyyMd` 는 거부한다).
- `MM` 과 `dd` 는 두 자리로 적힌 값만 읽는다 (`2026-3-1` 은 `yyyy-MM-dd` 로 읽히지 않는다). 한 자리도 받으려면 `M`, `d` 로 적는다.
- **날짜는 엄격하게 읽는다.** 없는 날짜(2월 30일)는 다른 날짜로 고쳐 읽지 않는다. 모양에 맞지 않는 값과 같이 그 행을 건너뛰고 행 번호와 이유를 남긴다. 읽을 때 언어 설정을 고정한다. [AD-166]
- 모양에 맞지 않는 값은 그 행을 건너뛰고 행 번호와 이유를 남긴다. [AD-94] [AD-71]
- **모든 칸에서 값의 앞뒤 빈칸을 떼고 읽는다.** 키든 값이든 같다. 값 가운데의 빈칸은 그대로 둔다. [AD-167]
- **빈 칸은 값이 없는 것이다.** 그 속성 값이나 관계를 만들지 않는다. 앞뒤 빈칸을 떼고 나서 빈 글자인 칸도 빈 칸이다. [AD-94] [AD-167]
- 앞 판에 값이 있었는데 새 판에서 비었으면 앞 값을 새 판의 적용일로 끝낸다. [AD-94] [AD-42]
- 새 판에서 행이 없어지면 그 행이 넣었던 속성 값도 새 판의 적용일로 끝낸다. 같은 개체의 같은 값을 다른 행이 여전히 넣고 있으면 끝내지 않는다. [AD-121]
- 항목의 키 열이나 주 개체의 키 열이 비어 있으면 그 행을 건너뛰고 이유를 남긴다. [AD-94]
- 주 개체가 아닌 개체의 키 열이 비어 있으면 그 개체와 그 속성 값을 만들지 않고 행의 나머지는 받는다. 키는 비었는데 그 개체의 속성 칸에 값이 있으면 그 행을 건너뛴다. [AD-175]
- **매핑이 쓰는 열과 반드시 있어야 하는 열은 모두 파일에 있어야 한다.** 하나라도 없으면 파일 전체를 거부하고 없는 열을 모두 알린다. [AD-174]
- **수는 값이 같으면 같은 표기가 되게 다듬어 저장한다.** 정수는 앞의 0 과 더하기 부호를 뗀다 (007 은 7, -0 은 0). 소수는 뒤의 0 을 뗀다 (3.50 은 3.5, 2.0 은 2). [AD-176]
- **키 열의 값 하나는 200자까지다.** 글자(코드 포인트)로 센다. 넘으면 그 행을 건너뛴다. [AD-177] 키 열의 값을 이은 항목의 키 전체도 200자까지다 (잇는 세로 막대와 역빗금을 넣어 센다). [AD-187]
- 정수와 소수는 부호 하나와 숫자(0 ~ 9), 소수이면 마침표 하나만 받는다. 지수 표기, 숫자 사이의 빈칸, 전각 숫자는 받지 않는다. 자릿수 구분 기호는 매핑에 적힌 글자만 뗀다. (구현하면서 정한 것, "결정 필요" 13번)
- 참·거짓은 매핑이 적은 두 글자와 글자 그대로 같을 때만 받는다. 적지 않았으면 `true`, `false` 만이다. 대소문자를 가린다. [AD-182]
- 출발과 도착이 같은 개체인 관계가 나오는 행은 건너뛴다. [AD-182]
- 한 판의 여러 행이 같은 개체의 같은 속성을 적었을 때, 기간이 서로 겹치지 않으면 부딪힘이 아니다 (한 파일에 이력을 여러 행으로 적은 것이다). 기간이 겹치는데 값이나 기간이 다르면 부딪힘이다. 부딪힘은 그 개체의 그 속성 전체로 본다: 둘만 겹쳐도 그 속성의 값은 이 판에서 어느 것도 넣지 않는다. [AD-136] [AD-179]
- 같은 관계를 여러 행이 겹치는 서로 다른 기간으로 적으면 그 관계는 넣지 않고 알린다. 행의 나머지는 받는다. [AD-180]
- 항목의 키가 겹치는지 볼 때는 값이 틀려 건너뛴 행도 센다. 키가 겹치면서 값도 틀린 행은 알림을 둘 받는다 (키 겹침과 자기 이유). 항목의 키를 읽지 못한 행(키가 비었거나 너무 긴 행)은 세지 않는다. [AD-157] [AD-181]
- 구현하면서 정한 것이다 ("결정 필요" 13번).
  - 유효기간의 열이 빈 칸이면 열이 없는 것과 같다: 시작일은 판의 적용일이고 종료일은 없다.
  - 종료일이 시작일보다 뒤가 아니면 그 행을 건너뛴다. 날짜는 0001-01-01 부터 9999-12-31 까지만 받는다.
  - 주 개체는 항상 만든다. 개체 정의 없이 관계의 끝으로만 적혀 있고 관계의 다른 끝이 비어 있어도 만든다. [AD-120]
- **한 판의 여러 행이 같은 개체의 같은 속성을 적을 때**: 값이 모두 같으면 한 번만 저장한다. 서로 다른 값이 있으면 그 속성 값은 어느 것도 저장하지 않고, 어느 행들이 어떤 값으로 부딪히는지 남긴다. 그 행들의 다른 내용은 그대로 들어간다. 행의 차례에 결과가 달라지지 않는다. [AD-136] 이때 앞 판의 값은 그대로 둔다. 끝내지 않고, 그 속성에 대한 변동도 만들지 않는다. [AD-146]

### 입력 파일

- 받는 형식은 CSV 와 엑셀(xlsx)이다. [AD-84]
- 첫 행은 열 이름이다. [AD-139]
- CSV 는 UTF-8 이다. 맨 앞의 표시(BOM)는 있으면 떼고 읽는다. UTF-8 로 읽히지 않는 바이트가 있으면 파일 전체를 거부한다. 엔진이 인코딩을 짐작하지 않는다. [link] [AD-169]
- **행 번호**는 파일에서 그 행이 시작하는 줄의 번호다. 열 이름의 줄이 1 이다. 아무것도 없는 빈 줄은 행으로 보지 않지만 줄 번호에는 센다. [AD-171]
- 칸 수가 열 이름의 수와 다른 행은 건너뛰고 행 번호와 이유를 남긴다. [AD-170]
- 열 이름과 칸의 값은 앞뒤 빈칸을 떼고 읽는다. [AD-167]
- CSV 를 읽는 그 밖의 세부는 구현하면서 정했다 ("결정 필요" 12번).
  - 칸은 쉼표로 나눈다. 쉼표, 큰따옴표, 줄바꿈이 든 값은 큰따옴표로 감싸고, 값 안의 큰따옴표는 두 번 적는다 (RFC 4180 의 적는 법).
  - 줄은 CR LF, LF, CR 가운데 어느 것으로 끝나도 된다. 감싼 값 안의 줄바꿈은 어떻게 적혀 있든 LF 하나로 읽는다. 같은 내용을 다른 줄바꿈으로 저장한 파일이 다른 값으로 읽히지 않게 한다.
  - 파일 전체를 거부하는 것: 열 이름의 줄이 없는 것(빈 파일), 열 이름이 비었거나 겹치는 것, 큰따옴표가 닫히지 않은 채 파일이 끝나는 것, 열 이름에 저장소가 받지 않는 글자(NUL)가 있는 것.
  - 그 행만 건너뛰는 것: 칸 수가 다른 행, 닫는 큰따옴표 뒤에 글자가 이어지는 행, 저장소가 받지 않는 글자(NUL)가 든 행.
  - 감싸지 않은 값 가운데의 큰따옴표는 글자 그대로 읽는다. 칸 앞의 빈칸 뒤에 나온 큰따옴표는 감싼 값을 여는 것으로 본다.
  - 감싼 값도 앞뒤 빈칸(줄바꿈 포함)을 뗀다. 값 가운데의 줄바꿈은 남는다. [AD-167]
  - 맨 앞의 표시(BOM)는 하나만 뗀다. 파일 가운데의 것은 글자로 남는다.
  - 빈칸만 든 줄은 빈 줄이 아니다. 칸 하나가 빈 행이다. 열이 둘 이상인 파일에서는 칸 수가 맞지 않아 건너뛴 행으로 남는다.
  - 열 이름의 줄이 쉼표로 끝나면(끝에 빈 열이 붙은 표) 열 이름이 비어 있으므로 파일 전체를 거부한다.
  - 앞뒤 빈칸은 유니코드의 공백 글자(전각 빈칸 포함)다. 줄바꿈하지 않는 빈칸(U+00A0)은 떼지 않는다.
- 파일 수준의 문제(인코딩, 반드시 있어야 하는 열 없음)는 파일 전체를 거부한다. 행 수준의 문제는 그 행만 건너뛰고 행 번호와 이유를 남긴다. [link]

### 엑셀 파일

- **엑셀은 화면에 보이는 대로 읽는다.** [AD-93]
  - 수식이 든 칸은 파일에 저장된 계산 결과를 읽는다. 엔진이 수식을 다시 계산하지 않는다.
  - 날짜와 숫자는 칸의 서식대로 보이는 글자를 읽는다.
  - 합쳐진 칸은 왼쪽 위 칸의 값을 채워 읽는다.
- 엑셀을 읽는 라이브러리는 Apache POI 다. link 모듈 안에서만 쓴다. [AD-93]
- 보이는 글자는 칸의 서식에 달려 있다. 같은 값이라도 서식이 다르면 다르게 읽힌다. 그래서 엑셀 열에는 매핑이 값의 모양을 적어 두는 것이 안전하다. 엔진이 서식을 글자로 바꿀 때 쓰는 지역 설정은 서버의 설정이 아니라 고정한 값을 쓴다. (제안. "결정 필요" 3번)
- 매핑이 지정한 시트 하나만 읽는다. 숨긴 행과 열도 읽는다. (제안. "결정 필요" 3번)

## 8. rules/ 와 questions/

- 규칙 파일은 `rules/` 에 둔다. 규칙의 형식, 조건식, 평가 순서, 조치의 모양은 D8 이 정한다. 이 문서는 적지 않는다. [AD-85]
- 검증 질문과 정답은 `questions/` 에 둔다. 형식은 D4 가 정한다. 정답은 대표가 정하고 임의로 고치지 않는다. [AD-85] [packs] [verify]
- 규칙과 검증 질문이 가리키는 유형, 속성, 입력 자료는 이 Pack 의 온톨로지와 매핑에 있어야 한다. 없으면 Pack 을 읽지 않는다. [보드 PACK-02]

## 9. 읽기, 검증, 적재

- 형식은 이 문서가 기준이다. 이 문서에 없는 항목을 읽기 편하다고 지어내지 않는다. [pack]
- **읽기**: 형식이 틀리면 파일 이름과 위치, 틀린 항목을 알려 주며 읽기를 멈춘다. [pack] [보드 PACK-01]
- **검증**: 읽은 정의가 서로 맞는지 본다. 정의되지 않은 유형이나 속성을 가리키는 곳, 상위 유형의 충돌, 돌아오는 상위 유형이 있으면 오류다. 오류가 하나라도 있으면 적재하지 않는다. 오류는 한 번에 모두 알린다. [pack] [보드 PACK-02] [AD-88] ("한 번에 모두"는 제안) 돌아오는 상위 유형은 고리 하나에 한 건을 알린다. 이미 알린 고리의 유형만으로 이루어진 다른 고리는 앞의 것을 고친 뒤에 드러난다.
- **적재**: 검증을 통과한 Pack 만 저장소에 넣는다. 전부 되거나 전부 안 된다. 같은 Pack 을 다시 넣어도 중복되지 않는다. [pack] [보드 PACK-03]
- 적재한 정의는 항목별 테이블에 담는다. Pack 자신, 개체 유형, 상위 유형, 관계 유형, 속성의 테이블은 D5 4절에 있다. [AD-69] [AD-125]
- **지금 읽는 것**: `pack.ttl`, `ontology.ttl`, `mappings/` 의 매핑 정의다. 매핑은 pack 이 읽고 검증해 저장하고, link 는 pack 의 공개 API 로 읽는다. [AD-140] 제약, 규칙, 검증 질문은 그 작업에서 읽는다. 그때까지 그 파일의 잘못은 적재에서 드러나지 않는다.
- 문제의 위치: 문법이 틀린 곳은 행과 열을, 정의가 틀린 곳은 파일 이름과 정의의 이름과 틀린 항목을 알린다. [AD-128]

### 고친 Pack 을 다시 적재할 때

이미 자료가 들어 있는 Pack 을 고쳐 다시 적재할 때 받는 것과 거부하는 것이다. [AD-95]

| 바꾼 것 | 처리 |
|---|---|
| 유형, 속성, 매핑, 규칙을 더함 | 받는다 |
| 이름표(`rdfs:label`), 표시 이름 속성, 영향 방향, 최대 깊이의 기본값, 규칙의 내용을 바꿈 | 받는다. 그 뒤의 계산부터 적용되고 이미 만든 조치는 그대로다 [AD-129] |
| 자료가 쓰지 않는 유형, 관계 유형, 속성을 지움 | 받는다 [AD-130] |
| 자료(유효기간이 끝난 것도 포함)가 쓰고 있는 유형, 관계 유형, 속성을 지움 | 거부한다. 무엇이 걸렸는지 알린다 |
| 상위 유형, 관계 유형의 출발·도착 유형, 속성이 속한 개체 유형을 바꿈 | 거부한다. 새 이름의 정의를 더한다 [AD-129] |
| 유형이나 속성의 이름 또는 형식을 바꿈 | 거부한다 |

- **지금의 구현은 지우는 것을 모두 거부한다.** 자료가 쓰는지 답하는 core 의 공개 API 가 아직 없기 때문이다. 그 API 가 생기면 표대로 고친다. [AD-130]
- 버전을 붙이고 이전 버전으로 되돌리는 것은 당김 범위다 (B-13).
- 영향 방향을 바꾸면 같은 변동 이벤트의 영향 범위가 전과 달라진다. 이미 만든 조치의 근거 경로를 어떻게 보여 줄지는 D5 "결정 필요" 5번(근거 경로를 저장하는가)에 달려 있다.

## 10. 결정 필요

2026-11-20 의 결정으로 앞 초안의 질문 7건은 닫혔다 (AD-87 ~ AD-95). 그 결정에서 새로 생긴 질문과 받아야 하는 것이다.

1. **하위 유형이 닿는 곳.** 하위 유형을 따르고 상위 유형을 여럿 허용하기로 했다 [AD-88]. 그러면 다음을 정해야 한다. (가) 영향 범위의 "개체 유형별 수"와 목록의 정렬은 구체적인 유형으로만 하는가? (나) 화면과 API 가 유형으로 거를 때 상위 유형으로 거르면 하위 유형의 개체도 나오는가? (다) 온톨로지를 아는 것은 pack 이고 core 는 유형의 이름만 저장한다. 관계의 출발·도착 유형이 맞는지 확인하는 것은 link 가 적재할 때 pack 의 공개 API 로 하는 것으로 보았다. 맞는가? (라) 규칙이 상위 유형에 걸릴 때의 평가는 D8 에서 정한다.
2. **제약의 보고.** 제약을 적재 뒤 전체 자료에 걸어 보고하기로 했다 [AD-92]. (가) 언제 거는가 (판을 적재할 때마다인가, 요청할 때인가)? (나) 어느 기준 날짜의 자료에 거는가? 유효기간이 끝난 관계와 속성 값도 보는가? (다) SHACL 의 어디까지 지원하는가 (개수, 자료형, 값의 범위, 유형. SPARQL 로 적는 제약은 지원하지 않는 것으로 제안한다)? (라) 위반을 어디에 저장하고 어디서 보여 주는가? 보여 주는 화면과 API 가 D7 과 보드에 없다. (마) 위반이 변동이나 조치로 이어지는가? (바) Jena 의 SHACL 검사는 RDF 그래프에 건다. 저장소의 개체와 관계를 RDF 로 바꾸는 일이 필요한데, 당김 범위인 RDF 내보내기(A-11)와 겹친다.
3. **엑셀을 읽는 세부.** (가) 서식을 글자로 바꿀 때 쓰는 지역 설정을 무엇으로 고정하는가? (나) 저장된 계산 결과가 없는 수식 칸은 건너뛰는가? (다) 매핑이 지정한 시트 하나만 읽고 숨긴 행과 열도 읽는 것이 맞는가? (라) 같은 내용의 CSV 와 xlsx 는 같은 판으로 보는가? 판의 `content_hash` [D5 5절] 를 파일의 바이트로 하면 다른 판이 된다.
4. (닫힘) 매핑 어휘는 확정했다 (AD-135 ~ AD-139, AD-146). 남은 것: 참조로만 만들어진 개체의 목록과 부딪힌 속성의 목록을 담는 투입 결과의 모양은 link 의 작업과 D7 에서 정한다 [AD-138] [AD-146].
5. **새 라이브러리의 확인.** Apache Jena 는 6.2.0 을 들였다 (`jena-arq`, pack 모듈의 빌드 파일 한 곳에 버전을 적는다) [AD-87] [AD-126]. Java 21 이 필요하다는 것과 보안 권고는 Jena 의 문서로 확인했다. 남은 것: (가) Jena 가 함께 들여오는 라이브러리(20여 개)의 라이선스 확인. (나) SHACL 검사를 만들 때 `jena-shacl` 을 더하는 것. (다) Apache POI [AD-93] 는 들일 때 같은 방식으로 확인한다.

7. (닫힘) 정의가 틀린 곳의 위치, 고친 Pack 의 나머지, 이름표와 이름의 세부는 정해졌다 (AD-127 ~ AD-134).
8. (닫힘) 자료가 쓰는 정의인지는 core 가 공개 API 로 답하고 api 가 물어 pack 에 넘긴다 [AD-159] [AD-130]. 구현은 그 API 를 만드는 작업에서 한다.
9. **언어 표시의 적는 법.** 언어 표시는 소문자로 바꿔 저장한다. 어떤 언어 표시를 받는지(예: `ko`, `en`, `ko-kr`)는 막지 않는다. 목록을 정해야 하는가? 빈칸만 있는 이름표(`"  "`)는 지금 받는다. 막아야 하는가?

10. (닫힘) 매핑의 검증 규칙은 확정했다 (AD-142 ~ AD-147). 판이 있는 입력 자료인지는 link 가 공개 API 로 답하고 api 가 물어 pack 에 넘긴다 [AD-159]. 구현은 link 가 생길 때 한다.

11. (닫힘) 날짜의 모양과 읽는 법은 정해졌다 (AD-165, AD-166). 칸의 앞뒤 빈칸도 정해졌다 (AD-167).

12. **CSV 를 읽는 세부.** 7절 "입력 파일"의 목록이다. 맞는지 확인이 필요하다. 그 가운데 판단이 갈릴 수 있는 것: (가) 줄바꿈하지 않는 빈칸(U+00A0)을 앞뒤 빈칸으로 보고 떼는가? 엑셀에서 옮긴 자료에 흔하다. 지금은 떼지 않는다. (나) 쉼표 말고 다른 구분 글자(탭, 세미콜론)를 매핑에 적을 수 있게 하는가? 지금은 쉼표만이다. 세미콜론으로 나눈 파일은 거부되지 않고 열 하나로 읽혀, 반드시 있어야 하는 열이 없다는 것으로 뒤에서 드러난다. (라) 끝에 빈 열이 붙은 열 이름의 줄을 거부하지 않고 그 열을 버리는가? 빈 열을 가진 엑셀 표에서 나오는 흔한 모양이다. 지금은 파일 전체를 거부한다. (마) 큰따옴표 하나가 닫히지 않으면 파일 전체를 거부한다. 어디서 행이 끝나는지 알 수 없기 때문이다. (다) 건너뛴 행의 이유의 코드 (지금은 `CELL_COUNT_MISMATCH`, `TEXT_AFTER_QUOTE`, `INVALID_CHARACTER`)와 파일을 거부한 이유의 코드는 D7 과 함께 확정한다 [AD-153].

13. **매핑 실행에서 구현하면서 정한 것 가운데 남은 것.** 대부분 확정했다 (AD-177 ~ AD-182). 남은 것: (가) 수의 표기 (지수 표기와 전각 숫자를 받지 않는 것), 빈 유효기간 칸, 종료일이 시작일보다 뒤가 아닌 행, 주 개체를 항상 만드는 것. (나) 건너뛴 이유와 거부의 코드 이름 (`BLANK_KEY`, `KEY_TOO_LONG`, `DUPLICATE_ITEM_KEY`, `VALUE_WITHOUT_KEY`, `INVALID_VALUE`, `INVALID_PERIOD`, `SELF_RELATION`, `MISSING_COLUMN`, `UNSUPPORTED_FORMAT`, `CONFLICTING_VALUES`, `CONFLICTING_PERIODS`, `STARTS_AT_EFFECTIVE_DATE`, `ALREADY_PAST`, `CANNOT_END`)은 D7 을 쓸 때 확정한다. 그때까지 바뀔 수 있다.
14. (닫힘) 아주 긴 키는 그 행만 건너뛴다 [AD-177]. 수를 틀리게 읽게 만드는 자릿수 구분 기호는 Pack 을 적재할 때 거부한다 [AD-178]. 남은 것: Pack 식별자, 유형 이름, 입력 자료의 식별자의 길이는 재지 않는다. 그것들이 아주 길면 200자 안의 키로도 식별자가 한도를 넘을 수 있다 (D5 "결정 필요" 10번).
15. (일부 닫힘, 2026-11-22) **제조 안전 Pack 을 만들면서 형식이 모자랐던 곳 (B-03).** 아래의 처음 셋(바뀐 열, 날짜나 다른 속성과 견주기, 입력 자료)은 규칙의 형식을 넓혀 닫았다 [AD-289] ~ [AD-292]. 형식은 D8 2절·3절에 있다. 제조 안전 Pack 의 규칙은 새 항목으로 좁혔고, 물질의 이름만 고친 판과 교육 이수일만 바뀐 인원이 시나리오에 들어가 검증 질문이 좁혀진 것을 본다. 나머지 셋은 남아 있다. 아래는 넓히기 전의 기록이다.
    - **행의 어느 열이 바뀌었는지를 규칙이 볼 수 없다.** 시연의 규칙은 물질안전자료의 유해성과 노출기준이 바뀔 때만 움직인다. 지금은 그 자료의 행이 어떻게 바뀌든 움직인다. 인원의 행도 같다: 배치 공정이 바뀐 것과 이름이 바뀐 것을 가르지 못한다.
    - **속성을 변동의 날짜나 다른 속성과 견줄 수 없다.** "교육 이수일이 자료의 개정일보다 앞선 인원만"을 적지 못한다. 견줄 값은 규칙에 적은 고정 값뿐이다.
    - **변동이 어느 입력 자료에서 나왔는지를 규칙이 볼 수 없다.** 그래서 규칙이 뜻보다 넓게 걸린다: 물질안전자료의 변경에 거는 규칙은 물질의 입력 자료의 행이 바뀌어도 걸리고 (그 행이 자료를 가리켜 자료도 변동 대상이 된다), 인원의 배치 변경에 거는 규칙은 인원을 가리키는 다른 입력 자료(이행 증빙)의 행이 더해져도 걸린다. 지금의 시나리오에는 그런 판이 없어 검증 질문에 드러나지 않는다.
    - **한 행이 여러 개체를 가리키면 그 모두가 변동 대상이 된다** [AD-59]. 물질안전자료의 행이 물질을 가리키면 물질도 변동 대상이 되어, 규칙이 "자료가 바뀌었다"를 가려내지 못한다. 그래서 물질과 자료를 잇는 관계는 물질의 입력 자료가 넣게 했다. Pack 을 만드는 사람이 알아야 하는 요령이다.
    - **관계의 도착 유형이 여럿이면 입력 자료를 유형마다 나눠야 한다.** 매핑은 관계의 양 끝의 유형을 하나씩만 적는다. "요건이 걸린 대상"은 물질, 보관소, 배출구, 설비의 입력 자료 넷으로, "사고에 관련된 것"은 설비와 물질의 입력 자료 둘로 나눴다. 한 매핑에 같은 관계 유형을 도착 유형만 달리해 두 번 적는 것을 엔진은 받아 주지만, 7절의 "같은 관계를 두 번 적으면 거부"가 그것을 허용하는지 분명하지 않아 쓰지 않았다. 7절에 "같은 관계"가 유형만인지 양 끝까지인지를 정해야 한다.
    - 시연의 신뢰도 채점과 격리, 응답의 가림(마스킹), 요건의 조건식은 형식에도 엔진에도 없다.

### 받아야 하는 것

6. (일부 닫힘) **제조 안전 Pack 의 내용.** `packs/manufacturing-safety` 를 채웠다 [AD-284] ~ [AD-288]: 유형 11개와 상위 유형 하나, 관계 유형 11개, 속성 26개, 입력 자료 20개, 규칙 6개, 예시 입력 파일, 검증 질문 26개 (규칙의 형식을 넓히며 넷을 더했다). 남은 것: 이 문서의 예시를 그 Pack 의 내용으로 바꾸는 일 [AD-86], 시연의 나머지 시나리오의 규칙.
