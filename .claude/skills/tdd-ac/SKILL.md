# 수용 기준을 시험으로: $ARGUMENTS

1. 수용 기준의 문장 하나마다 시험 이름 하나를 한국어로 적는다. 예: `시작일_당일은_유효하다`.
2. 일반 시험을 먼저 쓴다. 모듈별 최소 목록:
   - core: 빈 저장소, 관계가 없는 개체, 돌아오는 관계, 한 대상에 이르는 경로 여럿, 깊이 한계, 유효기간 경계(시작일 당일, 종료일 전날, 종료일 당일), 과거·현재·미래 시점
   - pack: 빈 Pack, 유형 하나뿐인 Pack, 참조가 끊긴 Pack, 같은 Pack 다시 넣기
   - link: 빈 파일, 첫 판, 바뀐 것 없는 판, 전부 바뀐 판, 행 순서만 바뀐 판, 잘못된 행, 같은 파일 두 번
   - rules: 규칙 없는 Pack, 해당 규칙 없음, 한 대상에 규칙 여럿, 같은 우선순위, 실패하는 규칙, 근거 조항이 빠진 규칙
   - api, web: 결과 없음, 권한 없음, 서버 오류, 잘못된 시점 값
3. 시험 자료는 지어낸 작은 값으로 만든다. 예시 Pack 의 값이나 정답 숫자를 시험 코드에 베끼지 않는다.
4. 데이터베이스가 필요한 시험은 Testcontainers 의 실제 PostgreSQL 로 돌린다. 메모리 DB 로 바꾸지 않는다.
5. 시험을 돌려 **실패하는 것을 확인**한다. 실패 이유가 "기능이 없음"이어야 한다. 컴파일 오류나 설정 오류로 실패하면 그것부터 고친다.
6. 결과를 같은 데이터로 두 번 비교하는 시험을 하나 둔다 (목록의 순서까지 같아야 한다).
7. 그 뒤에 구현한다. 시험을 통과시키려고 시험을 지우거나 약하게 고치지 않는다. 시험이 틀렸다고 판단되면 이유를 적어 사람에게 묻는다.

`superpowers:test-driven-development` 스킬이 있으면 그 절차를 함께 따른다.
