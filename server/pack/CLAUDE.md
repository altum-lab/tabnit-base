# pack — Pack 읽기, 검증, 적재 (주인 자리: B)

Pack은 업무 영역 하나의 지식 묶음이다: 온톨로지, 제약, 매핑, 규칙, 검증 질문. 이 모듈은 Pack을 읽어 내부 모델로 만들고, 서로 맞는지 확인하고, 저장소에 넣는다.

읽을 문서: D6 (형식의 기준). 관련 작업: SK-04, B-01, B-02, B-03.

## 맡는 것
- 읽기: 온톨로지와 제약, 매핑 정의, 규칙 정의.
- 검증: 형식, 참조 무결성(정의되지 않은 유형·속성을 가리키는 곳).
- 적재: 검증을 통과한 Pack만 저장소에 넣는다. 적재하는 것은 정의뿐이다. 개체와 관계는 넣지 않는다 (D2 AD-45).

## 지킬 것
- Pack의 형식은 D6이 기준이다. D6에 없는 항목을 읽기 편하다고 지어내지 않는다.
- 검증 오류는 **파일 이름과 위치, 틀린 항목**을 담는다. 오류가 하나라도 있으면 적재하지 않는다.
- 적재는 전부 되거나 전부 안 된다. 도중에 실패하면 되돌린다.
- 같은 Pack을 다시 넣어도 중복되지 않는다.
- 정의 파일은 RDF 의 Turtle 로, 제약은 SHACL 로 적는다. 읽는 라이브러리(Apache Jena)는 이 모듈 안에서만 쓴다. 다른 모듈은 내부 모델만 본다.
- D6 에 없는 문장이 정의 파일에 있으면 무시하지 않고 거부한다. 추론은 하위 유형 하나만 한다.
- 코드에 특정 Pack의 용어(설비, 조항 같은 유형 이름)를 넣지 않는다. 제조 안전 Pack과 퇴직연금 Pack이 같은 코드로 읽혀야 한다.
- Pack 의 정의는 이 모듈의 테이블에 담는다 (D5 4절). core 의 테이블에 쓰지 않는다. 다른 모듈은 이 모듈의 공개 API 로 정의(영향 방향, 최대 깊이의 기본값, 속성의 형식, 매핑, 규칙)를 읽는다.

## 하지 않는 것
- 규칙을 실행하지 않는다(rules). 입력 파일의 행을 옮기지 않는다(link).
- Pack과 규칙의 버전 관리(B-13)는 당김 범위다. 작업 카드가 있고 필수 범위가 밀리지 않을 때만 만든다 (D1 4절).
