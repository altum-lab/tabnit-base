# web — 관리 화면 (주인 자리: D, I)

React와 TypeScript. 변동 감지, 영향 범위, 조치와 확정, 관계 지도의 네 화면. 시연 앱의 화면을 옮겨 와 실제 API에 붙인다.

읽을 문서: D7. 관련 작업: D-01 ~ D-09.

## 지킬 것
- 서버와는 API로만 통한다. API 호출 코드는 OpenAPI 규격에서 만든 것을 쓰고 손으로 고치지 않는다.
- **화면에서 계산하지 않는다.** 영향 대상의 수, 조치의 기한과 우선순위는 서버가 준 값을 그대로 보여 준다. 화면이 다시 세거나 정렬 기준을 바꾸면 서버와 숫자가 달라진다.
- 시연 앱에 있던 고정 값과 가짜 응답은 연결하면서 지운다. 남겨 두면 실제 값처럼 보인다.
- 모든 화면에 조회 시점이 보인다. 시점을 바꾸면 그 시점으로 다시 받아 온다.
- 결과에는 근거로 가는 길이 있다(영향 대상 → 경로, 조치 → 근거 조항).
- API 실패와 대기 상태는 공통 처리로 보여 준다. 화면이 멈추거나 빈 화면이 되면 안 된다. 결과가 없을 때는 "영향 없음"처럼 없다는 사실을 말한다.
- 권한이 없는 동작의 버튼은 보여 주지 않는다. 그래도 최종 확인은 서버가 한다.
- 문구는 한국어. 용어는 D1의 용어집을 따른다.
- 화면 흐름 시험(Playwright)이 깨지는 변경은 끝난 것이 아니다.
- 고친 화면은 `playwright` MCP 로 실제로 열어 확인한다. 관계 지도의 성능은 `chrome-devtools` MCP 의 성능 기록으로 잰다.
- 호출 코드는 `npm run gen:api` 로 규격(`docs/api/openapi.yaml`)에서 다시 만든다. 만들어진 `src/api/schema.d.ts` 는 손으로 고치지 않는다. 서버는 `src/api/client.ts` 의 `api` 로만 부른다.

## 하지 않는 것
- 설정 화면(Pack, 커넥터), 사용자 관리 화면은 1월 범위다.
