## 1. 규칙 실행이란

영향 범위에 Pack 의 규칙을 적용해 해야 할 일(조치)을 만든다. [rules] [D3 8절]

```
변동 이벤트 ──▶ 변동 대상 ──(core: 영향 범위 계산)──▶ 영향 대상, 근거 경로
                                      │
                     Pack 의 규칙 ────┤
                                      ▼
                          (rules: 규칙 실행) ──▶ 조치 (근거 규칙, 근거 조항과 그 판, 대상, 기한, 우선순위)
```

- 순서는 api 가 잡는다. link 가 저장한 변동 이벤트를 api 가 읽어 core 의 영향 범위 계산과 rules 의 규칙 실행을 차례로 부른다. [AD-44]
- 규칙 실행기는 직접 만든 것을 쓴다. 외부 규칙 엔진을 들이지 않는다. [AD-14]
- 규칙의 내용은 Pack 에 있다. 특정 규칙의 조건을 코드에 넣지 않는다. [rules] [AD-01]
- 규칙 실행은 AI 모델을 부르지 않는다. [AD-02]

### 받는 것과 돌려주는 것

| | 내용 | 근거 |
|---|---|---|
| 받는 것 | 변동 이벤트 하나(변동의 종류, 변동 대상, 그 변동이 나온 판과 적용일) | [AD-44] [AD-58] |
| 받는 것 | 그 이벤트의 영향 범위 (영향 대상, 깊이, 근거 경로) | [AD-64] |
| 받는 것 | 그 Pack 의 규칙 목록 | [보드 RULE-01] |
| 받는 것 | 판의 적용일. 영향 범위와 조건의 속성 값은 적용일 전날과 적용일 두 날짜로 본다 (아래) | [AD-100] [AD-101] |
| 돌려주는 것 | 조치 목록 (새로 만든 것과 이미 있던 것) | [보드 RULE-02] |
| 돌려주는 것 | 평가에 실패한 규칙과 이유 | [rules] |

### 두 날짜

새 판에서 사라진 관계와 속성 값은 판의 적용일을 종료일로 넣어 끝낸다. [AD-42] 종료일은 제외이므로 적용일에는 이미 유효하지 않다. 적용일만 보면 없어진 것의 영향을 찾지 못한다. 그래서 두 날짜를 함께 본다.

- **영향 범위**: 변동의 종류와 상관없이, 적용일 전날의 관계로 한 번, 적용일의 관계로 한 번 따라가 두 결과를 합친다. 바뀌기 전에 이어져 있던 대상과 바뀐 뒤에 이어진 대상이 모두 든다. 같은 대상은 한 번만 세고, 근거 경로에는 어느 날짜의 관계로 닿았는지를 적는다. [AD-100]
- **조건의 속성 값**: 적용일의 값을 본다. 적용일에 값이 없으면 전날의 값을 본다. 두 날짜 모두 값이 없을 때만 "값 없음"이다. [AD-101]
- **합치는 일은 core 가 한다.** core 의 영향 범위 계산이 기준 날짜를 여럿 받아 합친 결과 하나를 돌려준다. api 는 변동 이벤트의 판에서 날짜 둘(적용일 전날, 적용일)을 구해 넘기기만 한다. core 는 그 날짜들의 뜻을 모른다. [AD-115]
- **같은 대상에 두 날짜 모두 닿으면** 더 짧은 근거 경로를 남긴다. 길이가 같으면 적용일 쪽(더 늦은 날짜)의 경로를 남긴다. 깊이는 남긴 경로의 길이다. 대상마다 경로는 하나다. [AD-116]
- **"한계에서 멈췄다"는 표시**는 합친 결과를 기준으로 켠다. 한 날짜에서는 한계 너머지만 다른 날짜에서 이미 찾은 대상이면 켜지 않는다. [AD-117]

## 2. 규칙 파일

- 규칙은 Pack 의 `rules/` 폴더에 Turtle 로 적는다. 항목은 이 제품의 어휘(`tabnit:`)로 적는다. [AD-96] [D6 2절]
- 규칙 파일은 pack 모듈이 읽어 내부 모델로 만들고, rules 모듈은 그 내부 모델만 본다. [AD-15] [AD-16]

```turtle
ex:rule-0001 a tabnit:Rule ;
    tabnit:ruleNo "0001" ;
    rdfs:label "규칙의 이름" ;
    tabnit:priority 1 ;
    tabnit:whenChangeKind tabnit:Changed ;
    tabnit:appliesTo tabnit:ImpactTarget ;
    tabnit:targetType ex:TypeB ;
    tabnit:condition [
        tabnit:subject tabnit:ImpactTarget ;
        tabnit:property ex:size ;
        tabnit:operator tabnit:GreaterThan ;
        tabnit:value 10
    ] ;
    tabnit:actionText "해야 할 일의 문구" ;
    tabnit:dueInDays 14 .
```

낱말의 이름은 모두 제안이다.

| 항목 | 반드시 | 뜻 | 근거 |
|---|---|---|---|
| `tabnit:ruleNo` | 예 | 규칙 번호. 글자다. Pack 안에서 겹치지 않는다. 글자 코드 순으로 비교한다 | [rules] [AD-103] |
| `rdfs:label` | 예 | 화면에 보일 규칙의 이름 | 제안 |
| `tabnit:priority` | 예 | 우선순위. 1 이상의 정수. 수가 작을수록 먼저다. 조치의 우선순위가 된다 | [rules] [AD-103] |
| `tabnit:whenChangeKind` | 아니오 | 어떤 종류의 변동에 걸리는가. 추가, 변경, 삭제. 여럿 적을 수 있다. 없으면 모든 종류 | [link] |
| `tabnit:appliesTo` | 예 | 조치의 대상이 영향 대상인지 변동 대상인지 | [AD-102] |
| `tabnit:targetType` | 예 | 조치를 만들 대상의 개체 유형. 그 하위 유형도 해당한다 | [AD-88] |
| `tabnit:condition` | 아니오 | 조건. 여럿 적으면 모두 만족해야 한다 | [AD-97] |
| `tabnit:actionText` | 예 | 조치에 담을 해야 할 일의 문구 | 제안 ("결정 필요" 1번) |
| `tabnit:dueInDays` | 예 | 기한까지의 일수. 0 이상의 정수 | [AD-99] |

- 규칙 번호는 글자 코드 순이라 `10` 이 `2` 보다 앞선다. Pack 을 만드는 사람이 `0002`, `0010` 처럼 자릿수를 맞춰 적는다. 한 Pack 안에서 규칙 번호의 자릿수가 서로 다르면 Pack 을 읽을 때 알려 준다. [AD-103]
- 대상이 변동 대상 자신인 규칙(`tabnit:appliesTo tabnit:ChangeTarget`)의 조건에 영향 대상을 보는 비교가 있으면 규칙 번호와 함께 Pack 을 거부한다. [AD-118]
- 규칙이 가리키는 유형과 속성은 그 Pack 의 온톨로지에 있어야 한다. 없으면 Pack 을 읽지 않는다. [D6 8절]
- 조건이 틀리면(없는 속성, 속성의 형식과 맞지 않는 비교나 값) 규칙 번호와 함께 Pack 을 거부한다. [보드 PACK-01.3] [보드 B-04]

## 3. 조건

조건은 비교의 목록이고 **모두 만족해야** 한다. "또는"은 없다. 필요하면 규칙을 둘로 나눈다. [AD-97]

### 조건이 볼 수 있는 것

| 대상 | 볼 수 있는 것 |
|---|---|
| 변동 | 종류 (추가, 변경, 삭제) |
| 변동 대상 | 개체 유형, 속성 값. 변동 대상이 여럿이면 그 영향 대상에 이르는 근거 경로가 시작한 변동 대상이다 [AD-64] |
| 영향 대상 | 개체 유형, 속성 값, 깊이 |

- 유형을 보는 비교는 하위 유형도 해당하는 것으로 본다. [AD-88]
- 속성 값은 적용일의 값이고, 없으면 전날의 값이다. [AD-101]
- 유형을 보는 조건은 `tabnit:typeIs` 로 적는다 (예: 변동 대상이 어느 유형일 때만). 시험용 Pack 의 규칙을 적다가 필요해서 더했다. (제안)
- 조건이 볼 수 있는 것은 위의 범위로 시작한다. 근거 경로가 거친 관계 유형, 바뀌기 전과 뒤의 값의 비교는 볼 수 없다. 예시 Pack 의 규칙을 적어 보고 표현할 수 없는 규칙이 나오면 그때 넓힌다. [AD-105]

### 비교 (제안)

| 비교 | 쓸 수 있는 형식 |
|---|---|
| 같다, 다르다 | 모든 형식 |
| 크다, 크거나 같다, 작다, 작거나 같다 | 정수, 소수, 날짜 |
| 목록에 있다 | 모든 형식 |
| 값이 있다, 값이 없다 | 모든 형식 |

- 비교는 속성의 형식에 맞춰 한다. 정수 `10` 과 `9` 는 수로, 날짜는 날짜로 비교한다. 글자로 비교하지 않는다. [AD-71]
- 글자의 같다·다르다는 글자 코드가 모두 같을 때 같다. 대소문자와 앞뒤 빈칸을 그대로 따진다. (제안)
- 소수의 비교는 표기가 아니라 값으로 한다 (`1.50` 과 `1.5` 는 같다). (제안)

### 값이 없을 때

적용일과 그 전날 모두 유효한 속성 값이 없으면 "값 없음"이다. [AD-55] [AD-101]

- "값이 없다"는 만족하고 "값이 있다"는 만족하지 않는다.
- 그 밖의 비교(같다, 다르다, 크다 등)는 **만족하지 않는다.** "다르다"도 만족하지 않는다. 값이 없는 대상까지 잡으려면 규칙을 하나 더 두어 "값이 없다"를 조건으로 적는다. [AD-104]
- 값이 없어서 조건을 만족하지 못한 것은 평가 실패가 아니다. 그 규칙이 그 대상에 해당하지 않는 것이다.

## 4. 평가 순서

같은 입력에는 같은 조치가 같은 순서로 나와야 한다. [rules] [C 8절]

1. 변동 이벤트 하나에 영향 범위 하나를 받는다. [AD-64]
2. 규칙을 우선순위, 규칙 번호 순으로 늘어놓는다. [rules] [보드 RULE-01.1]
3. 규칙마다 대상을 차례로 본다. 대상이 영향 대상인 규칙은 영향 범위가 준 순서(깊이, 개체 유형, 개체 식별자)대로, 대상이 변동 대상인 규칙은 변동 대상을 개체 유형, 개체 식별자 순으로 본다. [AD-61] [AD-102]
4. 변동의 종류, 대상의 유형, 조건을 모두 만족하면 그 규칙과 그 대상으로 조치 하나를 만든다.
5. 한 대상에 규칙 여럿이 해당하면 조치도 여럿이다. 규칙 하나가 대상 여럿에 해당하면 조치도 여럿이다. [AD-60]

- 규칙은 서로 독립이다. 한 규칙의 결과가 다른 규칙의 조건에 들어가지 않는다. 그래서 평가 순서는 결과의 내용을 바꾸지 않고 순서만 정한다. (제안)
- **돌려주는 조치 목록의 순서**: 우선순위(작은 수가 먼저), 규칙 번호, 대상 개체의 식별자. [AD-103] (대상 식별자를 셋째 기준으로 쓰는 것은 제안)

## 5. 조치

| 항목 | 값 | 근거 |
|---|---|---|
| 식별자 | 변동 이벤트, 규칙, 대상에서 정해진다 | [AD-60] |
| 근거 규칙 | 규칙 번호 | [rules] |
| 대상 | 영향 대상 개체. 규칙이 변동 대상에 거는 것이면 변동 대상 개체 | [보드 RULE-02] [AD-102] |
| 근거 조항 | 변동이 생긴 행의 주 개체. 매핑이 적는다. 행에 참조로만 나온 개체는 근거 조항이 되지 않는다 | [AD-120] |
| 근거 조항의 판 | 그 변동이 나온 입력 자료의 새 판 | [AD-98] [AD-41] |
| 근거 경로 | 변동 대상에서 대상에 이른 경로와, 어느 날짜의 관계로 닿았는지. 대상이 변동 대상 자신이면 비어 있다 | [AD-04] [AD-100] [AD-102] |
| 해야 할 일 | 규칙의 `tabnit:actionText` | 제안 |
| 기한 | 판의 적용일에 규칙의 `tabnit:dueInDays` 를 더한 날짜 | [AD-99] |
| 우선순위 | 규칙의 `tabnit:priority` | [rules] |
| 상태 | 대기로 만들어진다 | [AD-47] |

- **근거 조항이 없는 조치는 만들지 않는다.** 모든 매핑이 행의 주 개체를 적으므로 [AD-120] 변동 이벤트에는 언제나 근거 조항이 있다.
- 근거 경로는 근거 조항과 따로다. 근거 경로에는 실제로 시작한 변동 대상(행에 참조로만 나온 개체일 수 있다)을 적는다. [AD-120]
- **영향 범위와 조치는 판을 투입한 직후에 그때의 자료로 한 번 계산해 저장한다.** 다시 볼 때는 저장한 것을 보여 준다. 나중에 다른 자료가 들어와도 이미 만든 조치의 근거는 바뀌지 않는다. [AD-119]
- **넘겨받은 영향 범위는 rules 가 조치와 함께 트랜잭션 하나로 저장한다.** 규칙에 걸린 것이 없어도 영향 범위는 저장한다. 조치에는 근거 경로를 따로 적지 않고, 저장된 영향 대상으로 찾는다. 테이블은 D5 6절. [AD-209] [AD-210] [AD-211]
- 대상이 영향 대상인 조치에는 길이 1 이상의 근거 경로가 언제나 있다. [AD-34]
- **대상이 변동 대상 자신인 조치**는 근거 조항이 그 개체 자신이고 근거 경로가 비어 있다. 영향 대상 목록과 유형별·깊이별 수에는 지금처럼 변동 대상을 넣지 않는다. [AD-102]
- **기한**: 판의 적용일에 일수를 더한다. 달력의 날로 세고 주말과 공휴일을 따지지 않는다. 같은 변동은 언제 다시 실행해도 기한이 같다. 현재 시각을 읽지 않는다. [AD-99] [rules]

## 6. 다시 실행할 때

- 변동 이벤트, 규칙, 대상이 모두 같으면 같은 조치다. 같은 변동 이벤트로 규칙을 다시 실행해도 이미 있는 조치는 새로 만들지 않고 그대로 둔다. 상태와 이력도 그대로다. [AD-60] [AD-47]
- 규칙의 내용을 고친 Pack 을 다시 적재한 뒤에 실행해도 이미 만든 조치는 그대로다. 고친 내용은 새로 만드는 조치에만 들어간다. [AD-95]
- 다시 실행했을 때 전에는 해당하던 대상이 더는 해당하지 않으면(자료나 규칙이 바뀌어서) 이미 만든 조치를 어떻게 하는지는 "결정 필요" 2번.
- 뒤 단계가 실패하면 변동 이벤트를 실패로 표시하고 다시 실행할 수 있게 둔다. [link] [AD-44]

## 7. 실패

- 규칙 하나가 평가에 실패해도 나머지는 계속 평가한다. 실패한 규칙과 이유를 결과에 담는다. 조용히 건너뛰지 않는다. [rules] [보드 RULE-01]
- 조건이 틀린 규칙은 Pack 을 읽을 때 거부되므로 [2절] 실행 중에 만날 일이 없어야 한다. 실행 중의 실패는 저장된 값이 속성의 형식과 맞지 않을 때처럼 자료와 정의가 어긋난 경우다. (제안)
- 값이 없어서 조건을 만족하지 못한 것은 실패가 아니다 (3절).
- 규칙 실행 전체가 실패한 것(저장소 문제 등)과 규칙 하나가 실패한 것을 변동 이벤트의 상태에 어떻게 구분해 적는지는 D5 "결정 필요" 4번.

## 9. 결정 필요

2026-11-20 의 결정으로 영향 범위와 규칙 실행의 첫 작업을 막던 질문은 닫혔다 (AD-100 ~ AD-105, AD-115 ~ AD-118). 남은 것은 뒤에 정해도 된다.

### 뒤에 정해도 되는 것

1. **해야 할 일의 문구.** 규칙에 적힌 문구를 그대로 쓰는가, 문구 안에 대상의 표시 이름이나 속성 값을 끼워 넣을 수 있게 하는가? 끼워 넣는다면 그 표기와, 값이 없을 때 무엇을 넣는지를 정해야 한다.
2. **더는 해당하지 않는 조치.** 같은 변동 이벤트를 다시 실행했더니 전에 만든 조치의 대상이 더는 해당하지 않을 때, 그 조치를 그대로 두는가, 표시를 하는가? 대기인 것과 확정된 것을 다르게 다루는가?
3. **한 대상에 같은 일이 여럿.** 서로 다른 변동 이벤트가 같은 대상에 같은 규칙을 걸면 조치가 각각 생긴다 [AD-60]. 담당자가 같은 일을 여러 번 보게 된다. 화면에서 묶어 보여 주는가? D7 에서 정한다.
4. **규칙 번호의 자릿수.** 자릿수가 서로 다르면 "알려 준다"고 했다 [AD-103]. 알리기만 하고 읽는가, Pack 을 거부하는가?
5. **조건의 범위와 규칙 어휘의 낱말.** 시험용 Pack 의 규칙 셋(`packs/test-mini/rules/rules.ttl`)은 2절과 3절의 낱말로 적을 수 있었다. 유형을 보는 조건 `tabnit:typeIs` 하나를 더했다. 조건의 범위는 예시 Pack 의 규칙을 적어 보고 다시 본다 [AD-105]. 비교의 낱말(`tabnit:Equals`, `tabnit:GreaterThanOrEqual`, `tabnit:LessThanOrEqual` 등)과 변동의 종류의 낱말(`tabnit:Added`, `tabnit:Changed`, `tabnit:Removed`)을 2절의 표로 정리해야 한다.
6. **화면에서의 구분.** 조회 시점 하나로 보는 영향 범위와 변동 이벤트의 영향 범위(두 날짜를 합친 것)를 화면과 API 에서 어떻게 구분해 보여 주는가? 경로가 전날의 관계로 닿은 것인지 적용일의 관계로 닿은 것인지를 어떻게 보여 주는가? D7 에서 영향 범위 API 를 적을 때 정한다.
