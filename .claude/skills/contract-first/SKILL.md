# 계약이 먼저다

1. `docs/D7-api-contract.md` 와 OpenAPI 규격 파일에서 해당 API 를 찾는다. 규격에 없는 API 를 구현하지 않는다.
2. 규격을 바꿔야 하면 설계 변경이다. `/design-change` 를 실행하고 결정이 날 때까지 구현하지 않는다.
3. 결정이 났으면 규격 파일을 먼저 고친다. 확인할 것:
   - 관계를 읽는 API 는 조회 시점(`asOf`)을 받고, 응답에 어느 시점으로 답했는지 담는다
   - 결과에 근거로 가는 연결이 있다 (영향 대상의 경로, 조치의 근거 조항과 판)
   - 오류는 공통 오류 형식을 쓴다
   - 목록의 정렬 기준이 규격에 적혀 있다
4. 화면 호출 코드를 규격에서 다시 만든다 (`cd web && npm run gen:api`). 만든 코드를 손으로 고치지 않는다.
5. 서버 구현은 받고, 확인하고, 넘기고, 돌려주는 일만 한다. 계산과 판단은 해당 모듈의 공개 API 를 부른다.
6. 스프링 부트나 OpenAPI 도구의 사용법이 확실하지 않으면 `context7` 로 그 버전의 문서를 확인한다. 기억으로 쓰지 않는다.
